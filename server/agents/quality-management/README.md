# 质量管理与验收智能体

能力名：`quality.define_and_verify`。任务必须同时给出用户需求和任务目录中的受检目标。智能体先把需求拆成有方法、可判定的验收标准，再以独立视角检查文档、代码或两者，并输出 `acceptance-criteria.json` 与 `quality-assessment.json`。

## 工作边界

- 只接受相对任务目录的目标路径，拒绝路径穿越和绝对路径。
- 受检文件只读；不得为了“通过”而修改文档或代码。
- 使用 Codex CLI 分析需求、检查内容并在必要时运行安全验证命令；所有判断必须落到验收标准或发现项。
- Codex 分析没有默认总时限；运行期间会把子进程状态、累计时长及最近输出新鲜度作为协议心跳报告给中台，便于区分仍在处理与实例失联。
- 任一必要标准未通过时，结果带 `quality_acceptance_failed` 风险，是否接受由中台/人工审批规则决定。
- 自检只确认 Codex CLI 存在，不读取任何企业任务资料。

## 独立实例协议

中台会把允许检查的工件复制到质量节点的 `input/` 目录。共享运行时验证信封与目录边界、写入 `result.json` 并携带租约回调最终验收结果；验收失败不会直接改写原始 PPT，而是交给中台的单次返工策略处理。
