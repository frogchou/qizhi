# 栖知智能工厂服务端

桌面入口为栖知的「智能工厂」。操作员在「设置 → 智能工厂」中选择真实连接、填写服务地址和管理员令牌。219 测试服务器使用 `http://192.168.2.219:3010`，填写到端口即可。设置页的连接测试使用与工厂相同的鉴权。河谷演示使用本地模拟时钟，适合离线演示。真实模式运行中遇到断线会提示并恢复订阅。

## 从需求到画面

1. 接待大厅提交自然语言需求及验收方式。中台分配任务号，创建独立工作区，并在 PostgreSQL 和任务目录中记录接收事件。桌面入口记为 `qizhi_desktop`，Web 运维控制台记为 `console`，通用需求 API 默认记为 `api`。
2. 中台把任务目标与已审核能力交给规划器。工作区保留计划版本、依赖和会话，中台按可执行的节点并行申请实例。生产线展示的是版本和实际执行尝试；任务详情展示的是这一次任务采用的节点与前后关系。
3. 节点管理服务按已审核启动记录启动进程，实例回报启动、心跳、进度、结果或失败。运行时中心查看当前工作的归属及可取得的资源读数。业务后台把状态/时间线持久化，桌面由工厂事件接口获得变更并重新对齐统计与详情。
4. 验收按任务配置执行。等待人工的任务可在质检中心打开查看依据并处理；自动验收以后台的真实判断为准。交付中心列出已验收任务和可下载制品，下载沿用任务归属、实际文件及完整性检查。

| 建筑 | 权威数据 |
| --- | --- |
| 需求接待大厅 | 真实入口与 tasks.source_system；旧记录单列「来源未记录」 |
| 智能体中台 | tasks、task_plans、task_nodes、工作区会话与执行关系 |
| 智能体生产线 | 智能体身份、各版本注册状态和运行实例 |
| 质检中心 | 验收方式、验收记录、人工审批与退回记录 |
| 企业资产仓库 | 服务端凭据可访问且处于配置范围内的 RAGFlow 数据集；可从抽屉进入栖知知识库 |
| 运行时支撑中心 | 已登记运行时和正在支撑的任务、运行单元的资源采样 |
| 运行监控中心 | 持久化活动、实例心跳、需关注的任务 |
| 成果交付中心 | 已验收任务、已有制品清单与授权下载 |

## 项目位置与运行

同一栖知代码库中的 `apps/desktop` 负责客户端，`server` 是完整服务端工作区，包含控制平面、节点管理器、智能体、协议、迁移和原有运维控制台。两个工作区保留各自已锁定的 pnpm 版本。进入对应目录安装依赖，桌面按自己的方式构建；服务端从 `server` 运行 `corepack pnpm typecheck`、`corepack pnpm console:build` 和 `corepack pnpm test`。数据库测试须提供独立可丢弃的 `TEST_DATABASE_URL`。配置清单位于 `infra/env`，依赖数据库、系统服务的设置见服务端 README 及 `infra`。

219 延用 `/home/middleground/.worktrees/control-plane-ragflow-v1`、现有 systemd 服务名和现有数据目录。数据库里已审批的包与历史工单保存了绝对路径，发布时应把 `server/` 的内容放入现行部署目录。发布后由控制平面运行增量迁移，并同步节点管理器的就绪目录。运维网页保留在 `/console/`。

## 数据与接口边界

企业微信、微信、飞书、邮件等渠道需要实际的适配器；目前能提交需求的客户端、Web 和 API 在接待大厅中单独统计。RAGFlow 的密钥只在服务端使用，客户端获取数据集元数据。栖知的知识库页使用桌面端自己的 RAGFlow 配置。旧版数据库没有保存的来源、采集失败或无法归属的资源读数均保留其原有含义。

接口字段、分页和事件游标见 [工厂接口](../apps/control-plane/src/factory/README.md)。[注册与生命周期](../apps/control-plane/src/registry/README.md)、[数据库字段](../apps/control-plane/src/database/README.md) 和 [任务制品](../apps/control-plane/src/tasks/ARTIFACT_DELIVERY.md) 给出具体实现。
