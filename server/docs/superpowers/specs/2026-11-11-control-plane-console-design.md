# 中台控制台设计

## 意图

为企业管理员和开发者提供同一个 Web 控制台：提交自然语言需求信号、审核待启用智能体、查看已完成的智能体结果，并实时理解一个任务在中台和智能体群中走到了哪一步。用户不需要通过数据库或日志排查“是否卡住”。

## 目标

- 管理令牌在浏览器会话内输入和保存，不打包到前端资源。
- 提交需求后立即获得任务编号；后台执行持续上报实际智能体事件。
- 用统一流程视图呈现：需求接收、意图分析、任务编排、智能体执行、质量/结果验收；每步包含状态、起止时间、耗时和细节。
- 展示当前处理结果、证据、风险、产物和原始事件；每三秒刷新运行中任务。
- 列出智能体版本并可批准 `pending_review` 版本。

## 非目标

- 本轮不实现多租户、用户帐号、WebSocket、任务取消或通用自然语言执行图编译器。
- 现有知识库检索任务仍由当前的 `ragflow-knowledge` 可用能力执行；UI 不伪称尚未接入的运行时能力已经可以调度。

## 方案取舍

1. **独立前端进程 + 反向代理**：部署组件多且跨源认证配置额外。
2. **控制面同源静态控制台（采用）**：React/Vite 构建产物由控制面以 `/console/` 提供；浏览器与 API 同源，适合当前单机服务器。
3. **服务端 HTML**：部署简单但难以提供持续刷新、展开事件和交互式详情。

采用方案 2。控制面添加任务列表/详情接口，并将创建任务改为后台执行。流程状态由持久化任务、计划节点、尝试和事件组合，而非前端模拟。

## 界面设计

视觉稿为开发环境的本地参考，界面行为以控制台实现为准。

- 深蓝工作台；左侧需求列表与审批队列，中间纵向流程轨道，右侧选中节点的输入、输出、日志和风险详情。
- 顶部提供需求输入和提交；无令牌时显示登入覆盖层。
- 状态色：成功绿、执行中青、待审批琥珀、失败红、未开始灰。
- 窄屏时三栏改为单列，仍可查看完整时间线。

## 数据和接口

- `POST /v1/tasks`：返回 `{ taskId, state: 'running' }`，后台处理。
- `GET /v1/tasks`：返回最近任务摘要。
- `GET /v1/tasks/:taskId`：返回任务、计划、节点、尝试和有序事件，以及由这些记录推导的流程阶段。
- 既有 `GET /v1/agents` 和批准接口继续用于审批队列。

## 质量要求

- 后端查询/异步化以 Vitest 覆盖；React 组件逻辑以纯函数测试覆盖。
- 前端构建、现有全量测试、类型检查和实际浏览器点击流程必须通过。
- 每个新增模块目录附带 README；部署说明包含访问地址、端口和令牌处理方式。
