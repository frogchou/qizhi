# 任务可观测性与恢复设计

## 背景与问题

控制台目前以定时轮询展示任务详情。任务创建接口同步等待 Codex 规划，且顶层捕获异常后没有记录失败原因。发生依赖装配、目录发现或运行时故障时，任务会长期保留在 `planning`，前端只能显示笼统的“等待意图分析”。

智能体目录发现也没有面向管理员的逐包结果和失败审计；一个包的声明读取失败可能让后续包不再被登记，控制台因而没有可审批版本。

## 目标

1. 每个任务都拥有一条持久、顺序、可读且可续传的活动时间线。
2. 控制台通过受保护的 SSE 订阅实时接收任务状态、规划、调度、实例事件、结果与失败信息；断线后可按事件序号补发。
3. 需求提交立即返回任务，不因 Codex 规划阻塞 HTTP；控制面重启后能恢复未完成的规划。
4. 所有控制面、发现、调度和节点管理关键边界输出结构化、脱敏的 journald 日志，并在任务时间线留下用户可读摘要。
5. 智能体包逐一发现，任何一个包失败不会掩盖其他包；所有发现成功或失败结果有审计记录，待审核版本重新出现于控制台。

## 约束

- 保持“发现仅读取声明；人工批准后才首次自检”的既有安全策略。
- SSE 不在 URL 中携带管理员令牌。控制台先以 Bearer 令牌换取短期、单任务、一次性流票据；票据仅用于打开 SSE 连接。
- 时间线不保存管理员令牌、RAGFlow 密钥、完整 Codex 提示词、模型思维过程或原始运行时环境。
- 任务工作目录仍是任务会话、规划与工件的权威本地存储；数据库保存可查询索引与事件。
- 初期为单控制面服务实现内存发布器；持久事件和 `Last-Event-ID` 补发保证重连正确性，后续可在不改变 API 的前提下替换为跨节点发布器。

## 数据模型

新增只追加表 `task_activity_events`：

| 字段 | 含义 |
| --- | --- |
| `id` | 递增事件号，同时作为 SSE `id` |
| `task_id` | 所属任务 |
| `kind` | `task_received`、`planning_started`、`planning_completed`、`planning_failed`、`node_scheduled`、`agent_event`、`task_completed` 等稳定事件类型 |
| `state` | 该事件后任务或节点的状态 |
| `message` | 面向用户的脱敏中文说明 |
| `detail` | 已筛选的结构化细节（节点、实例、耗时、错误代码等） |
| `source` | `control_plane`、`node_manager` 或 `agent` |
| `occurred_at` | 产生时间 |

按 `(task_id, id)` 建索引，用于 SSE 首次回放及断线补发。

## 事件与接口

- `POST /v1/tasks`：同步写入任务与首个 `task_received` 事件，投递后台编排并立即返回。
- `POST /v1/tasks/:taskId/events/stream-ticket`：经管理员认证签发短期、单任务、单次使用的 SSE 票据。
- `GET /v1/tasks/:taskId/events/stream?ticket=...`：`text/event-stream`；先发送 `snapshot` 和历史事件，再推送实时事件；支持 `Last-Event-ID`。
- `GET /v1/tasks/:taskId`：保留为首屏快照和 SSE 断线恢复的后备接口。

## 可恢复后台流程

`TaskOrchestrationService` 以任务 ID 去重，并依次执行规划、编译、调度。每个阶段先写持久活动事件和工作目录状态，再调用外部运行时；任意异常写入 `planning_failed`/节点失败事件并记录关联日志 ID，不再由 HTTP 控制器吞掉。启动恢复时，对没有已编译计划的 `received`/`planning` 任务重新投递一次。

## 运行日志

使用统一 `OperationalLogger` 输出 JSON 到 stdout，由 systemd journald 收集。每条记录包含时间、级别、组件、事件、任务/节点/实例关联 ID、耗时和脱敏错误摘要。运行手册提供按任务 ID、组件、时间窗查询命令。前端读取的是持久活动时间线，不直接展示后端原始日志。

## 控制台表现

控制台显示 SSE 连接状态、最近更新时间和连续的“执行活动”时间线；每一项以中文显示阶段、节点/智能体、开始或结束时间、耗时和可读详情。保留原始 JSON 仅供开发者展开查看。SSE 断开时以明显但非阻塞的状态提示回退到详情拉取；重连后从最后事件号续传。
