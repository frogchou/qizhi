# 任务产物交付与人工返工设计

## 背景与问题

当前控制台将智能体结果中的 `artifacts[].path` 直接显示为文件名。该路径是节点工作目录内的相对路径，而控制面没有对应的受保护下载接口，因此管理员既不能下载 PPT，也不能打开 JSON 等交付材料。

质量智能体不通过时，调度器会清空 PPT 与质量节点的当前结果并自动重跑一次。旧的 PPT、质检报告和验收标准没有版本化归档，也没有被明确地传入下一次生成；管理员最终只能“确认验收”，不能决定是否带着失败意见返工。

## 目标

1. 每个已验证的智能体工件均有不可覆盖的任务内归档、可查询元数据和管理员授权下载入口。
2. 控制台有专门的“交付产物”区，能够下载文件、预览安全的文本型结果，并区分当前交付与历史返工版本。
3. 自动质量验收第一次不通过即进入人工决定；系统不再隐藏式自动返工。
4. 管理员可接受当前交付，或明确发起一次“根据质检意见返工”。
5. 返工保留已完成的资料检索，给 PPT 智能体提供上一版产物、验收标准、质检报告及可读的失败意见；返工后再次执行质量验证。
6. 每次产物归档、质量失败、人工决定、返工启动和完成均保留在数据库、任务会话及活动时间线中，便于审计和恢复。

## 非目标

- 不在本次实现面向浏览器直接编辑 PPT。
- 不引入公共或匿名下载链接；所有下载继续使用现有管理员身份验证。
- 不改变智能体包审核、节点管理或 Codex 运行时的权限模型。
- 不自动循环重试。后续每一次返工都需要新的人工确认。

## 任务状态机

```text
节点全部完成
      |
      +-- 质量通过且 platform_auto --> accepted
      +-- 质量通过且 human_review --> awaiting_review（管理员确认交付）
      +-- 质量不通过 -------------> awaiting_review（管理员：接受当前交付 / 返工）

awaiting_review --接受当前交付--> accepted
awaiting_review --根据质检意见返工--> running
running --PPT 与质量节点完成--> 按上列规则继续
```

仅质量不通过且图中存在可追溯 `presentation.create` 上游节点时显示返工操作。普通人工验收任务在质量通过时只显示“确认验收”。

## 数据与文件模型

### 数据库

新增 `task_artifacts`，用于将“经协议 SHA-256 校验成功的结果文件”登记为可交付工件：

| 字段 | 含义 |
| --- | --- |
| `id` | 不可猜测的工件标识，用于下载接口 |
| `task_id` | 所属任务 |
| `task_node_id` | 产生工件的节点 |
| `task_attempt_id` | 精确产生该工件的执行尝试 |
| `revision` | 对同一节点递增的交付版本号 |
| `original_path` | 智能体声明的节点内相对路径，仅作审计 |
| `storage_path` | 任务根目录内的归档相对路径，下载唯一读取此路径 |
| `file_name` | 供控制台展示与下载命名使用的安全文件名 |
| `media_type` | 由受控扩展名映射出的响应类型 |
| `sha256`、`size_bytes` | 完整性与展示信息 |
| `created_at` | 归档时间 |

在 `task_attempts` 增加 `result jsonb`，保留每次已接受的智能体结果，防止节点当前输出在下一次返工时被覆盖。`task_artifacts` 与尝试、节点和任务均受外键约束，并按任务和创建时间建立索引。

### 任务目录

验证成功后，控制面将文件从节点工作目录复制到任务目录下的稳定位置：

```text
<task-root>/
  artifacts/
    nodes/<node-id>/revision-<n>/<declared-relative-path>
  session/
    conversation.jsonl
    rework/<cycle>.json
  nodes/
    <ppt-node>/input/
      retry-context-<cycle>.md
      previous-quality-assessment-<cycle>.json
      previous-acceptance-criteria-<cycle>.json
      previous-presentation-<cycle>.pptx
```

归档文件只追加，不被下一次节点运行覆盖。`session/rework/<cycle>.json` 记录人工决定、来源尝试、质量失败摘要及构造出的返工输入；不得写入令牌、密钥或运行时环境。

## 接口契约

所有接口都使用已有管理员认证，且错误响应不泄露任务目录绝对路径。

| 接口 | 行为 |
| --- | --- |
| `GET /v1/tasks/:taskId` | 在任务详情中返回 `artifacts` 元数据列表；不返回服务器绝对路径。 |
| `GET /v1/tasks/:taskId/artifacts/:artifactId` | 校验工件归属后以安全响应头流式下载归档文件；始终校验该记录位于任务根目录内。 |
| `POST /v1/tasks/:taskId/review` | 请求体 `{ "decision": "accept" | "rework" }`。`accept` 仅允许任务处于 `awaiting_review`；`rework` 仅允许最近质量结果明确为不通过且存在可返工的 PPT/质量节点。 |
| `POST /v1/tasks/:taskId/approve` | 保留为兼容入口，语义等同 `review` 的 `accept`。 |

下载由控制台使用带 `Authorization` 的 `fetch` 获取二进制 Blob，再以浏览器下载方式保存；不会把管理员令牌放进 URL 或 DOM 链接。对于 JSON 等安全文本，控制台同时提供“查看内容”面板，仍从受保护接口读取。

## 返工执行机制

1. 质量节点以 `passed: false` 完成后，调度器写入质量失败活动并结束为 `awaiting_review`，不重置任何节点。
2. 管理员选择返工后，服务读取最新失败的质量尝试与其依赖的 PPT 尝试；创建新的返工周期记录。
3. 服务把上一版 PPT、质量报告、验收标准以及结构化失败原因复制到 PPT 节点新的 `input/` 文件，并写入中文 `retry-context`。资料检索节点保持 `completed`，避免重复查询。
4. 仅 PPT 节点和依赖它的质量节点转回 `pending`；旧节点输出仍可由历史尝试和 `task_artifacts` 查询。PPT 节点的静态输入增加返工上下文路径，新的尝试号自动递增。
5. 调度器照常启动 PPT 智能体；PPT 的 Codex 提示词将返工上下文视为必须阅读的改进约束，要求基于资料与失败原因修订，而非忽略上一轮结论。完成后重新运行质量节点。
6. 返工后的质量失败再次回到人工决定。系统不因次数自动接受或自动发起下一次返工。

## 安全与完整性

- 仅在 `InstanceResultsService` 已验证工件相对路径、文件存在且 SHA-256 匹配后，才复制归档并登记下载项。
- 工件下载通过数据库主键查找，验证 `task_id` 匹配，使用受限的 `storage_path`；拒绝绝对路径、`..` 穿越、符号链接逃逸和不存在的文件。
- 响应设置受控 MIME 类型、`Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`；未知类型按 `application/octet-stream` 下载。
- 浏览器不解析任意 HTML/SVG 为预览内容；初期只展示 JSON、文本和 Markdown 的转义文本预览。
- 返工上下文只引用任务内已验证、已归档材料。记录与活动事件继续经过现有敏感信息拦截。

## 控制台体验

“交付产物”区按当前版本在前、历史版本在后展示文件名、类型、来源节点、生成时间和校验摘要。每行提供“下载”；JSON/Markdown/TXT 还提供“查看内容”。

当质量不通过时，质量卡片明确标注“等待人工决定”，显示失败摘要和风险；标题区显示：

- `确认当前交付`：接受现有结果；
- `根据质检意见返工`：弹出确认说明，提示保留当前版本并重新执行 PPT 与质量节点。

返工开始、上一版材料已带入、PPT 重新启动、质量结果和新的交付版本均进入 SSE 时间线与实时控制台。控制台不会把文件内容、令牌或完整模型提示词推送到 SSE。

## 测试与验收

1. 工件结果回调成功后建立不可覆盖归档记录；SHA 不匹配、越界路径或非本任务工件不可下载。
2. 管理员可下载 PPT，JSON 可经认证获取并用于文本预览；无令牌、错误任务 ID、错误工件 ID 均被拒绝。
3. 第一次质量失败直接进入 `awaiting_review`，不会自动启动新的 PPT 尝试。
4. 人工 `accept` 使任务变为 `accepted`；人工 `rework` 仅重置 PPT/质量节点并保留检索节点。
5. 返工的 PPT 输入包含上一版 PPT、质量报告、验收标准和可读失败摘要；旧版仍可通过工件列表下载。
6. 控制台渲染交付下载区、质量失败决定区和返工后可读活动；完整测试、类型检查与生产构建通过后才部署。
