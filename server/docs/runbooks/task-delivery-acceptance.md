# 按用户需求验收与补查

中台在编排任务交付时把用户原话和提交时间交给独立的只读 Codex 调用。先列必需项与补充项，每项的依据必须是原话中的连续摘录。第二次调用核对交付答复、已校验的引用、归档文件和质管结果。后续轮次复用首轮有效标准。目录直答直接取自实时就绪目录，保留快速路径。原有质检不通过的文件返工仍由专门流程处理。

每项标记为已满足、缺少资料或待核实，并保留理由和证据编号。已满足必须引用实际存在的证据。模型失败、引用无效或仍有缺项时进入待人工验收。本版也把明确披露的补充缺项交给人决定，界面将其与必需项分开显示。用户已选择人工验收时始终等待人工决定。证据核对有输入长度上限，文件归档仅证明文件交付，语义核验仍由模型负责。

任务详情含按时间排序的 acceptanceRounds。对最新轮次调用 `POST /v1/tasks/:id/review`，提交 `{"decision":"accept","reviewId":"当前轮次 UUID"}` 或将 decision 改为 supplement。管理员令牌沿用原 API。请求锁定任务，已处理或不匹配的轮次返回 409。每次补查新增独立节点。已有内部能力或任务私有资料时使用已审核的 knowledge.retrieve，其余采用已审核的 research.web。补查节点，携带原问题、旧答复、来源摘录与缺项，沿用创建时刻。原始节点、文件及验收历史可继续查询。公开研究可补充证据；业务文件需要重新制作时仍使用对应返工流程。

在隔离数据库验证两条人工分支用 tests/control-plane/task-review.e2e-spec.ts。对指定旧自动通过任务的单次复核用 scripts/smoke/reassess-delivery.ts。它拒绝重评已有轮次或经人工签收的任务。真实补查重放用 scripts/smoke/research-review.live.ts，只读正式样本，把两种决策写入 middleground_test，在 127.0.0.1:39019 接收真实实例回调。运行期间不要同时重置测试数据库。
