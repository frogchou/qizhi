# Codex 运行时适配层

`CodexCliRunner` 是智能体调用本机已登录 Codex CLI 的唯一基础适配层。它为每次调用指定中台分配的任务目录，并把最终文本保存到该目录；不额外授权其他可写目录。

运行时以 `--output-last-message` 写入的非空最终消息作为已完成标志。CLI 正常退出时直接返回；若 CLI 在最终消息落盘后仍未退出，适配层会给予 500ms 收尾时间，然后终止该残留进程并把已落盘的最终消息交给调用方。取消请求优先于该收尾机制。

Codex 调用没有隐式的总时限：只有调用方明确传入 `timeoutMs` 才会启用硬超时。每个 Codex 子进程启动后立即、并在运行期间默认每 10 秒通过 `onStatus` 报告 `started` / `running`、已运行时长、是否产生输出和距最近输出的时长。PPT 与质量智能体把这些报告变成协议 `heartbeat`；中台规划器把它们写为 `planning_codex_status` 活动。两者都会持久化并经 SSE 推送到控制台。因此“进程仍在运行但暂无输出”和“进程已失联”可以被明确区分；前者不会被适配层按固定时长终止。

启动 CLI 时只传递本机登录、路径、区域、临时目录、XDG 配置目录和证书相关环境变量。中台的数据库、节点管理、RAGFlow 和管理令牌等变量不会继承到 Codex 子进程；业务凭据必须由对应的独立智能体在其受控执行路径中获取。

调用方必须把业务输入转成明确提示词，并自行校验 Codex 生成的业务产物。该适配层不保存令牌，也不记录提示词内容。
资料正文和历轮反馈进入提示时，运行器通过标准输入传给 `codex exec -`，以完整传递多字节文本，并避免命令行参数长度限制。附件的选择、读取权限、格式校验与可处理尺寸由对应业务智能体负责。
