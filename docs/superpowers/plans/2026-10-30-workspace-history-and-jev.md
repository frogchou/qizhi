# 工作文件历史与 JEV 价值分析实施计划

> 采用直接在 `main` 分支开发的方式。每项实现先补充失败测试，再完成最小实现并运行对应验证。

## 1. 时间范围索引查询

- 扩展索引 IPC，加入受限的 `ListRange` 查询和上限。
- 复用 NTFS 仓库的时间范围查询，并始终应用扫描策略、排除目录与文件类型过滤。
- 为五天历史范围、过滤与上限补充 Rust 测试。

## 2. 文件记录与历史快照命令

- 为本地文件记录增加价值分析字段及安全迁移。
- 增加“过去五天”快照命令并写入可被上传流程复用的记录。
- 保持今日刷新不阻塞：索引同步完成即可先返回列表。

## 3. TypeSafe JEV 服务

- 新增 JEV 客户端、服务配置与连通性测试，密钥仍只存 Windows 凭据管理器。
- 实现受限文本摘录、敏感文件跳过规则、评分映射与分析持久化。
- 在今日新文件刷新后以有限并发后台自动分析，记录成功、跳过和失败的诊断。
- 为资格判断、摘录限制、评分映射和配置验证添加单元测试。

## 4. 今日 / 过去工作台

- 将列表改为紧凑表格：复选框、文件名、时间、来源、价值评估、操作；表头可排序。
- 新增今日/过去标签；保留现有通配符和类型筛选。
- 将通知改为自动消失的浮层；主列表扩展到底部，活动区域放到右下辅助位置。
- 从价值单元和行菜单都可进入现有上传知识库对话框。
- 为标签切换、筛选排序、选择、价值上传入口与 toast 添加前端测试。

## 5. 验证与交付

- 运行 Rust 格式化、单元测试；运行前端测试、类型检查和生产构建。
- 审核默认不发送完整内容、不自动上传、历史查询不放宽扫描边界。
- 提交实现并重新打包 Windows 安装程序供用户验证。

## Review Focus

- 历史查询是否只返回允许目录中、未排除、受文件类型规则约束的项目。
- 文件修改后是否会触发重新价值评估，失败/无凭据是否不会阻断发现文件。
- UI 是否不产生横向溢出，长文件名、长标签和多选时是否保持可操作。
- JEV 请求是否从不包含绝对路径、完整文件或敏感文件内容。
