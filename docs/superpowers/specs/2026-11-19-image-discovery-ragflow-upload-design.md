# 图片发现与 RAGFlow 上传设计

## 目标与动机

栖知当前的 RAGFlow 上传链路可以发送任意本地文件，但扫描规则只接受文档、文本和源代码，导致图片在进入“今日 / 过去”工作区前就被过滤。此功能让用户按需发现近期图片，并把图片直接上传到 RAGFlow 知识库，同时避免图片淹没工作文件列表或误入 JEV 文档分析。

## 目标

- 在“设置 → 扫描与隐私”中提供独立、易理解的图片搜索开关。
- 在“今日 / 过去”的文件类型筛选中增加“图片”。
- 支持发现和上传 RAGFlow 已验证的常见图片格式。
- 图片行提供可见的上传入口，并继续保留右键上传。
- 维持现有文档、源代码、JEV 价值评估和目录聚合行为。

## 非目标

- 不在栖知内实现 OCR、图像描述、缩略图生成或视觉价值判断。
- 不替代 RAGFlow 知识库的 Picture、OCR 或视觉模型配置。
- 不让图片参与 JEV 自动价值评估或今日总结的文本提取。
- 本阶段不增加逐格式开关、图片尺寸阈值或像素尺寸过滤。

## 已选方案

### 方案 A：独立开关，共用扫描类别模型（采用）

在现有 `fileCategories` 中增加 `images`，设置页以独立的“图片搜索”区域控制该类别。图片发现默认关闭；用户启用并保存后，今日和过去工作区才会接收图片。类型下拉框始终提供“图片”，便于用户理解能力边界。

优点是与当前扫描、查询、目录聚合和上传校验共用同一套规则，不引入第二套路径或重复持久化。旧设置没有 `images` 时自然保持关闭，升级不会突然把大量图片加入列表。

### 方案 B：文件类型区域增加一个普通复选框（未采用）

实现最少，但“图片搜索会显著扩大结果量”和“图片不参与 JEV”的差异不够醒目，用户容易误以为它和普通文档完全相同。

### 方案 C：默认启用图片（未采用）

能立即发现图片，但用户目录、Pictures、网页资源和代码项目素材可能带来数千条记录，与栖知强调工作文件和低干扰的目标冲突。

## 支持格式

首期固定支持：

- `.jpg` / `.jpeg`
- `.png`
- `.webp`
- `.tif` / `.tiff`
- `.gif`

这些格式覆盖 RAGFlow Picture 解析文档明确列出的 JPEG/JPG、PNG、TIF、GIF，并补充当前 RAGFlow 文件类型识别代码支持的 WebP。SVG、BMP、AVIF、RAW、PSD 等格式暂不进入发现范围，避免不同 RAGFlow 版本和解析路径的兼容性差异。

## 交互设计

### 设置页

“扫描与隐私”下新增独立卡片“图片搜索”：

- 开关文案：`在今日和过去中发现图片`
- 默认状态：关闭
- 说明：启用后发现 JPG、PNG、WebP、TIF 和 GIF；图片不会交给 JEV 评估，上传后的 OCR 或视觉描述由目标 RAGFlow 知识库决定。
- 保存仍使用现有“保存扫描范围”动作，保存成功提示继续反馈扫描范围、排除目录和图片状态。

旧配置和新安装默认都保持图片搜索关闭。启用图片不改变扫描目录，只改变索引结果进入工作区的文件类型。

### 今日 / 过去

- 文件类型下拉框增加 `图片`。
- `所有支持类型`包含文档、源代码和图片，但实际结果仍受已保存的扫描规则约束。
- 图片文件使用现有文件类型图标体系；没有对应图标时补充清晰的图片图标。
- 图片的价值评估列显示 `图片 · 不评估`，不显示“评估中”。
- 图片操作列同时显示“打开”和“上传”；右键菜单继续提供“上传到知识库”。
- 上传仍使用现有知识库选择、目录和“上传后开始解析”对话框。
- 图片搜索关闭时，选择“图片”显示空态，并提示前往设置启用图片搜索，而不是报告扫描失败。

### 总结与 JEV

- JEV 自动和手动评估继续只接受文档与文本。
- 目录统计中的图片计入“不评估”。
- 今日总结解析选择时忽略图片；如果最终没有可总结的文档，提示“今日总结仅支持文档与文本”。

## 数据与兼容性

- Rust `FileCategory` 和 TypeScript `FileCategory`、`WorkspaceCategory` 增加 `Images / images`。
- `default_file_categories()` 保持 `Documents + SourceCode`，确保新安装和旧设置都默认关闭图片。
- 现有 JSON 设置无需迁移；缺少 `images` 即表示关闭。
- `FileTypeFilter` 成为图片格式判断的唯一后端来源，今日查询、上传校验和目录聚合共享该判断。
- 前端兼容旧桌面命令的本地筛选分支同步增加图片格式，但不另建持久化规则。

## 错误与安全边界

- 文件仍必须位于允许扫描范围内，且不能命中排除目录。
- 保存图片搜索设置后，旧查询令牌按现有机制失效或刷新，不允许利用旧列表绕过新规则上传。
- 文件在上传前仍检查存在性和普通文件属性；RAGFlow 拒绝格式或解析失败时展示服务端错误，不伪报上传成功。
- 栖知不读取图片内容用于 JEV，也不为发现目的生成缩略图，避免额外隐私暴露和扫描成本。

## 验收标准

1. 默认设置下，今日 / 过去不显示图片。
2. 开启图片搜索并保存后，受支持图片可通过“图片”和“所有支持类型”筛选显示。
3. 文档与文本筛选不混入图片，源代码筛选也不混入图片。
4. 图片不会触发 JEV 自动或手动评估，界面显示“图片 · 不评估”。
5. 图片可从行内操作和右键菜单打开上传对话框，并通过现有 RAGFlow multipart 接口上传。
6. 关闭图片搜索并刷新后，图片立即从工作区消失，旧查询不能继续上传该图片。
7. 目录聚合、搜索、排序和批量选择对图片保持正常。
8. 旧扫描设置可正常加载，图片搜索状态为关闭。
