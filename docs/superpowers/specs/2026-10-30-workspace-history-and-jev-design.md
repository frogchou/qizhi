# 工作文件历史与 JEV 价值分析设计

## 目标

将“今日”从一次性的当天列表扩展为工作文件入口：默认快速查看今天的文件，也能查看过去五天内已由本地 NTFS 索引发现的工作文件。新发现、符合安全规则且可以提取文本的文档默认交给 TypeSafe System One JEV 分析价值，给出“值得入库 / 工作资料 / 不建议入库”的建议；任何上传仍必须由用户主动确认。

## 本期范围

- 今日、过去两个标签页；过去页默认查询今天之前五个自然日。
- 复用现有 NTFS 索引数据库，新增带时间范围的受扫描范围、排除目录和文件类型规则约束的查询。
- 今日文件使用带表头、可排序、可勾选的紧凑表格；高价值文件可直接进入现有上传知识库流程。
- 将刷新、同步、分析状态改为自动消失的悬浮提示，不占用主内容区域。
- 将“今日活动”收纳到列表右下的辅助区域，移除低价值的常驻“选择文件”详情栏。
- 新增 JEV 服务设置与连通性测试；默认地址为 `https://api.typesafe.ai`，默认模型为 `jev-latest`。
- 自动分析仅处理新发现、允许展示、未被本地敏感规则拦截、且能安全提取有限纯文本的文件。初版支持文本、Markdown、JSON、CSV、YAML、HTML/XML 和常见源代码；Office/PDF 暂不把原始二进制上传给模型，保持“待人工评估”，后续接入解析器后再启用。

## 非目标

- 不在本期实现全盘任意日期、任意通配符的 Everything 等价检索；该能力需要单独的全文/名称投影、分页和存储边界设计。
- 不自动上传任何文件到 RAGFlow。
- 不向 JEV 发送整个文件、文件绝对路径、二进制内容或被规则判为敏感的文件。

## 数据与隐私边界

本地索引查询先使用已配置的扫描范围、排除目录和文件类型过滤，再产生 UI 候选文件。JEV 输入仅包含文件名、扩展名、大小、修改时间及最多 48 KiB 的本地文本摘录；路径不发送。文件名匹配 `.env`、credential、secret、token、password、key、cookie 等敏感模式时跳过自动分析。JEV 分数、置信度、标签和分析所对应的文件修改时间保存在本地记录中；文件修改后必须重新分析。

## JEV 调用

使用 System One API：`POST /v1/systemone`，Bearer 凭据从 Windows 凭据管理器读取。每个文件请求包含 `model: "jev-latest"`、结构化 `state` 和一个 `score` 问题。评分标准从低到高为：瞬时配置/缓存、个人工作草稿、项目交付物、可复用组织知识。分数大于等于 2 且置信度足够时标记“值得入库”；低置信度显示“待人工确认”。

自动任务在本地索引刷新完成后异步运行，限制并发与单次数量，失败仅记录诊断日志并保留可重试状态，不影响文件列表可用性。

## 验收标准

1. 默认显示今天；点击“过去”能在不重新遍历磁盘的情况下显示过去五天的受限文件。
2. 两个列表均可按文件名、修改时间、来源与价值排序，并可按类型和通配符筛选。
3. 表格有复选框，价值为“值得入库”的条目可打开目标知识库上传对话框。
4. 刷新与分析进度使用自动消失的悬浮提示；主列表在宽度受限时不出现横向溢出。
5. 具有已配置 JEV 凭据时，合格新文本文件自动得到可持久化的 JEV 价值结论；无凭据、被跳过或接口失败时列表仍完整可用。
