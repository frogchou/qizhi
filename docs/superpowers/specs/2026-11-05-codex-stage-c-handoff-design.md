# Codex 阶段 C：跨页面资料交接与 RAGFlow 回传设计

## 1. 背景与意图

阶段 A+B 已实现本机 Codex 检测、项目与连续会话、项目资料快照、流式任务和生成物管理。阶段 C 要补齐栖知内部的资料闭环：用户在“今日/过去”或知识库问答中发现资料后，不必重新在文件选择器中寻找它们；用户也能把 Codex 生成物经明确确认上传到 RAGFlow。

本阶段最重要的不是增加三个按钮，而是避免跨页面交互割裂。用户必须始终清楚：选中了什么、资料发送到哪个项目和会话、传递是否完成、跳转后下一步做什么。页面跳转不得承担文件传递本身，传递成功状态必须先由 Rust 与 SQLite 确认。

## 2. 已确定的产品选择

采用“目标选择弹窗 + 自动跳转”方案：

1. 用户从来源页面选择文件、片段、完整文档或知识库回答。
2. 点击“发送到 Codex”。
3. 在统一弹窗中选择目标项目和会话；最近使用的目标默认选中并置顶。
4. 后端完成校验、快照、去重和交接记录后，前端才切换到 Codex 工作。
5. Codex 打开目标会话，在输入框上方显示“本轮重点资料”卡片。
6. 用户补充任务要求后手动发送；栖知不自动调用 Codex。

弹窗内允许直接新建项目或新会话，但不再进入第二个页面。首次使用需要完整选择；后续保留最近目标，主按钮可直接“发送并继续”。

## 3. 目标与非目标

### 3.1 目标

- 今日/过去单文件、多文件和聚合目录选择均可交接到 Codex。
- 知识库检索片段、引用原文档以及带引用的最终回答可交接到 Codex。
- 资料进入项目后有稳定快照、来源、哈希和交接批次；切换页面或重新渲染不会丢失。
- 跳转后自动打开正确的项目和会话，并明确显示刚加入的资料。
- Codex 生成物可选择目标 RAGFlow 知识库、知识库内目录和是否立即解析后上传。
- 本地来源变化后可由用户手动刷新快照；历史轮次继续保留旧版本绑定。

### 3.2 非目标

- 不自动执行 Codex 任务。
- 不自动上传任何生成物到 RAGFlow。
- 不把整个聚合目录隐式授权给 Codex；必须解析为当时明确可见且符合规则的普通文件。
- 不把 RAGFlow Agent 的私有思考内容或执行过程作为资料发送。
- 不把“发送到 Codex”做成新的文件移动操作；原文件和 RAGFlow 数据不被修改。
- 本阶段不实现独立的全局“资料篮”。

## 4. 方案比较

### 4.1 方案一：目标弹窗后自动跳转（已选）

优点是目标明确、误发风险低，且能在跳转后自然进入任务输入。代价是首次交接需要一次项目/会话选择。通过最近目标、原位新建和默认选择降低重复操作。

### 4.2 方案二：全局 Codex 资料篮

适合跨页面长期收集，但引入新的产品概念；用户容易忘记资料是否已经放入篮中、是否已经进入项目。当前不采用。

### 4.3 方案三：一键发送到最近会话

点击最少，但资料可能进入错误项目，尤其不适合公司资料和敏感内容。未来可在方案一稳定后作为显式快捷入口，当前不采用。

## 5. 总体流程与可靠性交接

```text
来源页明确选择
    ↓
后端准备清单：重新校验权限、存在性、类型、数量、大小
    ↓
目标弹窗：项目、会话、新建入口、资料清单、警告
    ↓ 用户确认
后端暂存全部快照/下载内容并计算哈希
    ↓
数据库事务：资料版本 + 交接批次 + 会话待用资料
    ↓ 成功返回 handoffId
App 切换到 Codex，并指定 projectId/conversationId
    ↓
CodexPage 从数据库读取 handoffId，不依赖来源页内存
    ↓
展示“已加入 N 项资料”及本轮重点资料卡片
```

只有提交成功才跳转。提交失败时来源页面和原选择保持不变，弹窗逐项显示原因并允许重试。多项资料先全部进入项目内 staging 目录，全部成功后再提交数据库；失败则清理本批新建的 staging 文件，避免半个批次被误认为完成。

交接使用客户端生成的 `requestId` 保证同一次确认重复点击不会创建重复批次。两个来源路径不同但内容相同的本地文件保留为两个独立 material，以便分别检测源变化和刷新；底层内容寻址快照可按哈希复用物理文件。RAGFlow chunk ID、dataset/document ID 相同的远程资料复用现有 material。已存在资料仍可加入本次“重点资料”。

项目有运行中任务时禁止向该项目导入、刷新或移除资料，目标弹窗将项目标为“任务进行中”，避免活动轮次读到中途变化的资料集合。

## 6. 来源页面交互

### 6.1 今日/过去

- 有选择时，列表顶部批量操作区增加“发送到 Codex”。
- 单个文件右键菜单增加同名操作。
- 聚合目录被选择时，使用现有 workspace query 快照解析为明确文件 ID；提交前再次应用扫描范围、排除目录和文件类型规则。
- 弹窗摘要显示文件数、总大小、最多前五个文件名和其余数量。
- 超过 50 MB 的单文件沿用大文件二次确认；旧版 Office 被标为阻塞项，用户需从批次移除后继续。抽取失败但原件仍可安全复制的现代文档允许用户以“仅原件、读取能力不确定”方式确认加入；普通源码和项目文件允许作为原始快照加入。
- 成功后清除本次已发送选择，并显示短暂提示；若用户返回来源页面，不会重复发送。

### 6.2 知识库问答

知识库回答区提供三种明确粒度：

1. **检索片段**：片段卡支持勾选，批量“发送片段到 Codex”。每个片段生成结构化 Markdown，包含正文、知识库/文档/chunk ID、文档名、相关度和检索时间。
2. **完整原文档**：引用资料卡增加“发送原文到 Codex”。Rust 直接从 RAGFlow 下载到项目 staging，不先写入用户下载目录；随后走与本地文件相同的快照和派生文本流程。
3. **本次回答**：每个 Agent 的最终回答分别提供“发送此回答到 Codex”，不自动合并多个 Agent。生成 Markdown 包，包含 Agent 名称、用户问题、该 Agent 最终回答和可验证引用片段；不包含私有思考或执行轨迹。类型记录为 `ragflow_answer`。没有可验证引用的回答仍可发送，但弹窗明确标为“无引用的回答快照”，不得展示为经过知识库验证的内容。

没有可下载 document ID 的来源只能发送片段，界面不得把“片段”伪装成完整文档。多个引用指向同一文档时，完整文档只下载一次。

### 6.3 统一目标弹窗

弹窗包含：

- 当前资料摘要及来源标签。
- 最近使用目标，默认选中最近打开且非运行中的项目和其最近会话。
- 项目下拉与会话下拉；会话列表随项目变化。
- “新建项目”“新建会话”原位操作。
- 大文件、不可下载原文、已存在资料、目标项目运行中等提示。
- 阻塞项必须先移除；“仅原件、读取能力不确定”和“无引用回答”需要明确确认，但不阻止其他有效资料。
- 次按钮“取消”，主按钮“发送并继续”。

弹窗记住本次应用会话内最后成功目标，但每次仍显示目标名称，不做无提示的一键发送。

## 7. Codex 会话承接

App 顶层新增受控导航请求，只携带 `projectId`、`conversationId` 和 `handoffId`。资料正文和文件路径不经 React 路由传递。

CodexPage 收到请求后：

- 选择目标项目与会话并读取未消费交接。
- 在固定输入框上方显示“本轮重点资料”横向卡片，包括来源图标、名称和数量。
- 顶部短暂提示“已加入 N 项资料，可输入任务要求”。
- 用户可从本轮重点资料中移除某项；这只取消本轮强调，不删除项目资料。
- 用户切换到其他会话再回来时，待用资料仍在。
- 发送任务成功创建本地 turn 后才把 handoff 标为已消费；启动失败时保留待用资料，允许重试。

项目中的全部有效资料仍属于该项目可读上下文；“本轮重点资料”会在发给 app-server 的任务文本前加入由后端生成的资料路径提示，使 Codex 优先使用这些资料。数据库中的用户消息仍只保存用户原始指令，扩展后的内部提示不冒充用户输入。

每个 turn 继续通过现有 `codex_turn_material_versions` 绑定当时项目内全部可读资料版本，准确记录 Codex 当时实际具备的读取范围；新增 `codex_turn_handoffs` 记录本轮明确强调的交接批次。这样既能解释完整可读边界，也能区分用户本轮重点选择了哪些快照，且不修改旧轮次。

## 8. 数据模型

新增 migration `0012_codex_handoffs.sql`：

### 8.1 `codex_handoffs`

- `id`
- `request_id`（唯一，防重复提交）
- `source_kind`：`today | recent | ragflow_chunks | ragflow_document | ragflow_answer`
- `project_id`
- `conversation_id`
- `status`：`preparing | ready | consumed | failed | cancelled`
- `created_at_utc_ms`
- `consumed_at_utc_ms`
- `error_summary`（不含正文和绝对路径）

### 8.2 `codex_handoff_items`

- `id`
- `handoff_id`
- `material_id`
- `material_version_id`
- `display_name`
- `source_metadata_json`（受控结构，仅保存 ID、名称、相关度、时间等）
- `display_order`
- `state`：`ready | dismissed | consumed`

### 8.3 `codex_turn_handoffs`

- `turn_id`
- `handoff_id`

用于记录某一轮明确采用的“本轮重点资料”；完整可读资料版本仍由现有 `codex_turn_material_versions` 保存。

### 8.4 `codex_artifact_uploads`

- `id`
- `artifact_id`
- `dataset_id`
- `parent_path`
- `content_hash`
- `document_ids_json`
- `status`：`uploading | uploaded | uploaded_parse_failed | uncertain | failed`
- `start_parsing`
- `created_at_utc_ms`
- `completed_at_utc_ms`
- `error_summary`

`codex_materials.kind` 允许 `local | ragflow_chunk | ragflow_document | ragflow_answer`。`origin_reference` 不再承载随意拼接文本，新数据使用结构化来源元数据；旧数据保持兼容。

## 9. 后端服务与命令

### 9.1 交接准备与提交

- `prepare_codex_handoff(input) -> CodexHandoffPreview`
  - 输入只含来源记录 ID、query ID、受长度限制的 chunk/回答字段和候选目标；完整文档始终由后端根据 dataset/document ID 重新下载。
  - 重新解析 Today 选择、验证知识库来源并计算数量/大小/警告，不复制文件。
- `commit_codex_handoff(input) -> CodexHandoffResult`
  - 输入含 `requestId`、目标 project/conversation、来源选择和大文件确认。
  - 校验会话属于项目、项目无运行任务。
  - staged snapshot/download → hash/dedupe → DB transaction。
- `list_pending_codex_handoffs(conversation_id)`
- `dismiss_codex_handoff_item(handoff_id, material_id)`

Today 前端不能传任意路径；Rust 依据现有文件记录 ID 重新取路径并应用扫描策略。知识库完整文档只接受 RAGFlow 返回并保存在当前会话结果中的 dataset/document ID 组合；片段 Markdown 在后端以受控模板生成。

### 9.2 Turn 扩展

`StartCodexTurnInput` 增加 `handoffIds`。后端从 handoff 读取并校验版本，构造内部资料提示；创建 turn 后照常绑定项目全部可读版本，并通过 `codex_turn_handoffs` 记录重点批次，然后把 handoff 标为 consumed。前端不能提交任意 material ID。

### 9.3 生成物上传

- `upload_codex_artifact(input) -> RagflowUploadOutput`
  - 参数：project ID、artifact ID、dataset ID、parent path、start parsing、重复上传确认。
  - 后端从 artifact ID 解析受控相对路径，拒绝路径穿越、符号链接、重解析点、已删除或运行中仍在写入的文件。
  - 复用 `RagflowClient::upload_document`，不使用 shell/curl。
  - 记录上传状态与返回的 RAGFlow document IDs。

若上传请求已发出但响应中断，标记为 `uncertain`，不自动重试，以免在 RAGFlow 中产生不可见重复文档。用户可明确选择再次上传。

### 9.4 资料刷新与移除

- 本地资料比较来源文件当前哈希；变化时显示“源文件已变化”。
- 用户确认“刷新快照”才建立新 material version。
- RAGFlow 原文档可手动重新下载生成新版本；片段和回答作为当时快照，不自动刷新。
- 正在运行任务时禁止刷新或移除。

## 10. 生成物上传界面

Codex 右栏生成物操作增加“上传知识库”。点击后打开与今日上传一致但信息更完整的确认弹窗：

- 文件名、大小、生成会话和修改时间。
- 目标知识库下拉。
- 知识库内目录（可选）。
- “上传后立即解析”默认开启。
- 若相同 content hash 已上传到同一知识库，显示上次结果并要求再次确认。

上传过程中只锁定该操作；成功后生成物卡显示目标知识库和解析状态。失败不影响本地生成物。Codex 任务运行且文件可能继续变化时禁止上传该项目生成物。

## 11. 错误、并发与恢复

- 来源在确认前被删除、排除或修改：中止提交并要求刷新清单，不偷偷发送旧路径。
- 文件在 staging 复制期间变化：通过复制前后元数据与最终哈希检查；不稳定文件失败。
- RAGFlow 下载失败：不创建 ready handoff，不跳转。
- 目标会话被归档或不属于项目：拒绝提交并重新选择。
- 页面切换发生在提交中：提交继续由后端完成；成功结果写入 DB，用户下次进入对应会话仍可看到。
- 同一 request ID 重试：返回已有成功结果；失败批次可用新 request ID 重试。
- 应用异常退出：ready 且未消费 handoff 在重启后仍保留；preparing 批次在启动恢复时标为 failed 并清理 staging。
- 运行中项目：禁止资料集合变化和生成物上传，避免读写竞态。

## 12. 安全与隐私

- 所有本地文件仍经过扫描范围、排除目录、文件类型与规范路径校验。
- 前端永远不向 Codex command 传项目根绝对路径；后端从 ID 解析。
- RAGFlow 来源元数据不保存 API Key、回答私有思考或完整请求日志。
- 常规日志只记录批次 ID、项目 ID、数量、状态和脱敏错误，不记录正文、文件名全路径或用户指令。
- 上传 RAGFlow 必须由用户确认目标知识库和解析设置。
- 资料快照和生成物权限继续使用阶段 A+B 的 Codex permission profile，不扩大本机读取范围。

## 13. 测试策略

### 13.1 Rust

- Today 单文件、多文件、目录选择解析和规则重校验。
- 本地文件删除、修改、排除、类型改变、大文件与不稳定复制。
- request ID 幂等、内容哈希去重、跨项目 material ID 拒绝。
- RAGFlow chunk/document/answer 模板、引用去重、私有思考不落盘。
- 完整文档下载失败不产生 ready handoff。
- staging 清理、DB 事务失败与重启恢复。
- 运行项目拒绝导入/刷新/上传。
- artifact ID 安全解析、重复上传、解析失败和 uncertain 状态。
- turn 成功消费 handoff，启动失败保留 handoff。

### 13.2 React

- 今日/过去批量操作和单文件右键入口。
- 统一目标弹窗默认最近目标、切换项目刷新会话、原位新建。
- 提交失败不跳转，成功后才导航。
- Codex 会话显示待用资料，跨页面和跨会话不串线。
- 移除重点资料不删除项目资料。
- 知识片段、完整文档和回答三个粒度入口。
- 生成物上传确认、重复提示和状态反馈。

### 13.3 端到端

1. 今日选择两个文件 → 发送到现有会话 → 自动跳转 → 输入任务 → Codex 能读取快照。
2. 选择聚合目录 → 确认解析出的明确文件清单 → 新建会话 → 任务绑定正确版本。
3. 知识库发送片段和完整文档 → 断开 RAGFlow → Codex 仍能读取本地快照。
4. Codex 生成 Markdown → 选择知识库上传并解析 → RAGFlow 返回 document ID。
5. 提交过程中切换页面或重启应用，ready handoff 不丢失、不重复。

## 14. 验收标准

1. 用户从来源页最多经过一次目标弹窗即可进入正确 Codex 会话。
2. 默认目标是最近使用且可写的项目/会话，目标名称始终可见。
3. 导入成功前不跳转；失败后来源选择与错误信息保留。
4. 跳转后立即看到本批资料卡片，切换页面或会话后仍可恢复。
5. Codex 能读取本批本地文件、知识片段或 RAGFlow 原文档，并能解释资料来源。
6. 相同资料重复发送不会复制多份快照，但可以成为新的本轮重点资料。
7. Agent 私有思考不会进入 Codex 资料。
8. 生成物只有在用户确认目标知识库和解析设置后才上传。
9. 上传失败不删除或修改本地生成物；不确定结果不会自动重试。
10. 任何跨项目 ID、路径穿越、符号链接或运行中资料变更均被拒绝。

## 15. 实现者可决定的细节

- 弹窗精确尺寸、图标、过渡动画和最近目标展示条数。
- 资料卡片折叠阈值与文件名截断策略。
- staging 目录的清理周期和上传历史保留时长。
- RAGFlow 回答 Markdown 的排版，只要保留问题、最终回答和可验证引用且不包含私有思考。
