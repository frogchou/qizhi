# 栖知（Qizhi）桌面工作台：项目设计

**状态：待批准（已补充实施批次决策）**  
**范围：Windows-first 的长期维护桌面产品**  
**本文件不包含任何服务地址、API Key 或其他可用凭据。**

## 1. 意图与产品定位

栖知面向以电脑文件为主要工作载体的职场人员。它在本机发现工作痕迹、帮助用户回顾当天的工作、经用户同意后将有价值的材料沉淀到 RAGFlow，并提供基于知识库的问答与受控的 Codex 复杂任务入口。

Everything 只解决“快速发现哪些文件存在”。栖知必须独立承担内容抽取、价值判断、隐私过滤、重复检测、活动归因、外部服务调用和用户授权。产品的核心承诺是：**本地优先、可解释、可撤销、用户对每一次外发有最终控制权。**

首发平台为 Windows 10/11 x64。Everything 是首发依赖；macOS/Linux 不是首发范围。

## 2. 已确认的用户体验

界面遵循已批准的“栖知”原型，左侧主导航固定为：`今日`、`知识库`、`Codex 工作`、`设置`。

### 今日

- 显示当天新增或变更的文件；后续可纳入浏览器历史等其他活动源。
- 每条文件显示文件名、时间、来源、价值状态和“定位”动作。
- 价值状态为：建议入库、待确认、不建议；它不是自动上传指令。
- 用户勾选文件后，才能打开“加入知识库”确认流程。
- “生成今日总结”根据本地活动和已获许可的内容分析产生可编辑草稿。

### 知识库

- 用户选择一个或多个 RAGFlow 知识库并提问。
- 调用 RAGFlow 已配置的问答能力，展示回答、引用来源、检索范围和连接状态。
- 没有可验证来源的回答必须清楚标注为“未找到充分依据”，不伪造引用。

### Codex 工作

- 搜索本机文件与知识库片段；用户通过“引用”将材料显式加入任务上下文。
- 用户撰写任务要求后，界面展示将要发送给 Codex 的确切材料、工作目录与授权模式。
- 提交后展示任务阶段、流式日志摘要、生成物位置和失败原因；能取消任务。
- 首发只支持本机配置的 Codex CLI 适配器。WorkBuddy/其他代理集成定义为后续可插拔适配器，不作为首发承诺。

### 设置

- 用户管理扫描根目录与排除目录；系统目录和回收站默认且不可被移入扫描范围。
- 用户配置 Everything、OpenAI 兼容端点、JEV、RAGFlow 与 Codex CLI。
- 密钥只保存到操作系统凭据库；设置页、日志和诊断包只显示掩码。
- 每个服务均有“测试连接”与可读的诊断结果。

## 3. 目标、非目标与反目标

### 目标

1. 在已授权目录中快速、稳定地发现当天活动文件，并可在系统资源管理器中定位。
2. 以明确的风险/价值理由帮助用户决定是否将文件加入知识库。
3. 通过 RAGFlow 管理上传、解析、切片与问答；上传前始终由用户确认。
4. 让用户在一个可审计的界面中把精确选择的材料交给 Codex 完成复杂任务。
5. 从第一天具备可测试、可迁移配置、可发布、可扩展适配器和版本化数据模型。

### 非目标（首发不做）

- 不替代 Everything 的索引器，不扫描系统目录，也不构建全盘内容索引。
- 不在后台自动上传任何文件；不在未确认时将完整文件内容发送给 OpenAI、JEV、RAGFlow 或 Codex。
- 不训练用户数据模型；不做云端账号体系、团队协作或远程同步。
- 不直接实现或承诺 WorkBuddy 的私有接口；仅保留将来接入的端口。
- 不保证所有格式均能完整抽取。无法可靠抽取时保持“待确认/无法分析”，不猜测内容。

### 反目标

- 不能成为“无感收集并上传所有办公文件”的工具。
- 不能把模型建议伪装为确定事实或绕过用户授权。
- 不能将 API Key、文件原文或敏感字段写入源代码、日志、崩溃报告、测试夹具或版本库。

## 4. 方案比较与已选方案

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Tauri 2 + React/TypeScript + Rust 本地层 | 轻量、原生系统能力强、可在 Rust 中封装 Everything IPC/文件权限/凭据与进程管理 | 需要维护前后端边界与 Rust 适配器 | **采用** |
| Electron + React + Node.js | Node 生态成熟 | 包体积与运行时开销更大，原生安全边界较弱 | 不采用 |
| 本地服务 + 浏览器前端 | 初期实现快 | 后台监控、资源管理器操作、密钥与 Codex 权限体验较差 | 不采用 |

### 已确认的实施批次与运行策略

- **当前开发批次：阶段 0–1。** 交付工程地基、设置与密钥安全存储、Everything 发现、受限目录扫描、今日文件列表和资源管理器定位。阶段 2–4（模型分析、RAGFlow 上传/问答、Codex 任务执行）保留契约和 UI 入口，但不在本批次调用真实业务 API。
- **OpenAI 模型策略：** 应支持 `gpt-5.6` 或更高版本。实际模型 ID 不在代码中硬编码；首次连接时从兼容端点的模型列表探测可用模型，并在设置页只将符合该策略的模型作为默认/推荐选项。若端点不支持模型枚举，允许用户手动填写模型 ID，并在保存前做无内容的连接验证。
- **RAGFlow 问答策略：** 用户在设置或知识库页面选择现有问答机器人/Assistant；不根据知识库自动替用户选定机器人。
- **Codex 策略：** 后续阶段使用 Windows 原生 Codex CLI。当前批次不启动 Codex 进程；为阶段 4 预留受控的每任务工作目录和原生路径接口。

## 5. 运行时架构

```text
React 桌面界面
        │  仅调用受控 Tauri commands/events
Tauri/Rust 应用层
        ├─ Domain services（扫描、归因、判定、上传编排、任务编排）
        ├─ Ports（抽象接口）
        ├─ SQLite 本地数据库 + 迁移
        ├─ OS 凭据库 + 文件系统/进程权限
        └─ Adapters
             ├─ Everything SDK（首选）/ es.exe（后备）
             ├─ 本地内容抽取器
             ├─ JEV System One
             ├─ OpenAI-compatible API
             ├─ RAGFlow HTTP API
             └─ Codex CLI（Windows/WSL 可配置）
```

UI 不可直接访问磁盘、密钥、外部 HTTP 或启动进程。所有请求经 Rust 应用层进行输入校验、授权检查、审计记录和取消管理。第三方服务被建模为可替换适配器，避免业务逻辑依赖具体 URL、SDK 或请求格式。

### 5.1 核心领域对象

- `FileRecord`：稳定文件标识、路径、时间、大小、扩展名、哈希、发现来源、扫描许可状态。
- `ContentSnapshot`：本地抽取结果、抽取器版本、页/表/段落概要、敏感标记；原文不复制进业务日志。
- `ActivityEvent` / `WorkCluster`：文件变化与可解释的工作活动归因。
- `Assessment`：价值、敏感性、重复性、建议知识库、置信度、理由、判定器版本和人工覆写。
- `UploadProposal`：文件集合、目标知识库、解析器/切片策略、原因、状态和用户确认记录。
- `KnowledgeSource` / `Citation`：RAGFlow 数据集、文档、片段及其可追溯来源。
- `CodexTask`：引用材料清单、任务文本、受控工作目录、授权模式、运行状态、输出清单与审计摘要。

这些对象和状态机在 `packages/contracts` 中作为版本化 schema 定义；前端、Rust 层与测试夹具共享同一契约。

## 6. 隐私、权限与密钥规则

1. 初次运行采用许可向导：选择扫描根目录、确认默认排除项、配置服务，并单独同意外部内容传输。
2. 扫描只读取用户许可根目录；强制排除 Windows、Program Files、AppData、Recycle Bin 及用户添加目录。符号链接、网络路径、受保护路径默认跳过并提示。
3. 每次可能发送内容到外部服务前，先显示服务名称、文件/片段、传输目的和用户选择；用户可以取消。后台扫描和本地规则判断不构成外发许可。
4. JEV 用于结构化价值/敏感/目标知识库判定。若发送任何内容到 JEV，必须符合该文件的外部分析许可；否则只用本地元数据或保持未知状态。
5. OpenAI 仅用于已许可的内容分析、今日总结和用户主动的生成请求；绝不作为后台全量文件分析器。
6. RAGFlow 上传是两阶段操作：生成提案 → 用户确认 → 上传/解析/轮询。解析失败保留可重试状态，不重复上传同一哈希。
7. Codex 只可见用户明确引用的材料，运行在每任务独立的受控工作目录。默认权限为“建议”，提升为可写/可执行前需用户在任务页确认。
8. API Key 使用 Windows Credential Manager（经 Rust keyring 封装）保存；数据库只持有引用名。导出、日志和诊断数据一律脱敏。

## 7. 关键业务流程

### 7.1 今日文件与总结

1. `FileDiscovery` 通过 Everything 返回受允许范围内按时间变化的候选文件。
2. `Scanner` 进行路径策略、稳定性检查（避免读取仍在写入的文件）和增量去重。
3. `ContentExtractor` 按类型本地抽取；失败时记录原因，不调用模型补猜。
4. `AssessmentService` 先做本地规则/重复检测，再在可授权时调用 JEV 得到结构化判定；低置信度进入“待确认”。
5. `ActivityService` 聚类文件时间、路径和可选的未来活动源，生成可解释的工作簇。
6. 用户点“生成今日总结”后，界面展示将使用的活动簇；在已授权内容范围内调用 OpenAI，生成可编辑草稿。

### 7.2 入库建议与 RAGFlow 上传

1. 读取 RAGFlow 可用数据集及其描述/标签。
2. 根据文件类型、摘要与用户配置规则推荐目标知识库和解析策略；JEV 返回固定选项和理由，不能直接执行上传。
3. 对提案展示文件、目标库、解析器、切片策略、估计风险、重复项与将要发送的服务。
4. 用户确认后执行上传，记录本地哈希到远端文档 ID 的映射，轮询解析状态。
5. 解析结果、失败与人工调整回写到提案；允许打开 RAGFlow 对应文档（如实例支持）。

默认策略映射：PDF/Office 长文按 RAGFlow 文档类解析；表格优先选择表格/问答友好策略；Markdown/纯文本使用通用分段；图片/扫描件明确要求 OCR 能力。实际策略名、模板参数和 RAGFlow 版本差异由 `RagflowAdapter` 通过能力探测确定，不能硬编码在 UI 中。

### 7.3 知识库问答

1. 用户选择数据集、已配置的问答机器人/Assistant 和问题。
2. `RagflowAdapter` 选择已配置的问答机器人/会话并提交请求。
3. UI 显示答案、可展开引用、服务错误与“回答未找到依据”状态。
4. 会话本地可删除；默认不把聊天记录上传到非 RAGFlow 服务。

### 7.4 Codex 复杂任务

1. 用户搜索/引用本机文件或知识库片段。
2. `TaskPlanner` 显示精确任务包：任务文本、引用清单、来源说明、临时工作目录、Codex 预设权限。
3. 用户确认后 `CodexRunner` 在独立目录调用已配置的 CLI；Windows 原生或 WSL 路径由设置页检测。
4. 进程输出被结构化为安全摘要；原始日志只在本机、按保留期可删除。
5. 输出文件标记为应用生成物，展示位置，并可选择加入知识库（再次走上传确认）。

首发不假定 WorkBuddy 有公开可用接口。若日后接口可用，增加 `AgentRunner` 适配器，不改动界面和领域模型。

## 8. 项目组织、质量与发布

```text
apps/
  desktop/                 # React UI、Tauri 壳、Rust 应用层
packages/
  contracts/               # 版本化领域 schema 与错误码
  ui/                      # 复用 UI 基元与主题 token
  test-fixtures/           # 无真实内容/无真实凭据的测试样本
docs/
  architecture/            # ADR、威胁模型、接口契约
  superpowers/specs/       # 已批准设计和计划
```

- 使用 `pnpm` workspace、Rust workspace、TypeScript strict、格式化与 lint 门禁。
- 数据库迁移、配置 schema 和应用版本均可回滚/兼容检查；任何破坏性迁移先备份本地数据库。
- 所有适配器拥有 fake 实现与契约测试；UI 不依赖真实网络服务完成测试。
- CI 包含格式化、静态检查、单元测试、Rust 测试、构建和打包冒烟测试。真实凭据仅在开发者机器的本地手工连接测试中使用。
- 发布产物有版本号、变更日志、Windows 安装包、自动更新清单、签名策略和回滚说明；代码签名证书配置为发布前置条件，不纳入代码库。
- 提交前初始化 Git 仓库；忽略 `.superpowers/`、运行数据、`.env*`、密钥存储导出和测试产物。

## 9. 分阶段交付与验收

### 阶段 0：工程地基

建立 Tauri 工作区、设计系统、契约、SQLite/迁移、凭据库、配置向导、日志脱敏、CI 与发布骨架。验收：无真实服务时所有 UI/领域测试可运行，设置不以明文落盘。

### 阶段 1：本地发现与今日界面

实现 Everything SDK/CLI 探测、受限目录扫描、文件列表、资源管理器定位、增量数据库和可解释的演示级本地活动归因。验收：在用户选定目录中能稳定显示当天文件；系统目录不进入结果。

**当前批准候选交付：阶段 0–1。** 阶段 2–5 需要在阶段 0–1 验收后另行排期和批准。

### 阶段 2：内容理解与今日总结

实现本地抽取、哈希去重、JEV 判定端口、OpenAI 总结端口、人工覆写与外发授权弹窗。验收：未授权时不产生外部请求；授权后可生成可编辑总结并显示材料范围。

### 阶段 3：RAGFlow 知识库

实现数据集发现、上传提案、确认、解析状态、策略映射与知识库问答。验收：对测试文件能完成“提案—确认—上传—解析—引用问答”闭环，重复上传可识别。

### 阶段 4：Codex 工作区

实现引用、任务包预览、CLI 检测/启动、取消、输出管理及 Windows/WSL 诊断。验收：只向 Codex 暴露已引用材料，用户能看见输出与错误；未授权的写入/命令不会执行。

### 阶段 5：可靠性与发布候选

性能测试、升级迁移、异常恢复、无障碍、隐私审计、安装/卸载/更新验证和真实环境手工验收。

## 10. 验收指标

- 在包含至少 10,000 个候选路径的许可范围内，首次“今日文件”查询的目标交互响应小于 2 秒（不含首次内容抽取）。
- 所有外发前均有可检查的用户确认记录；测试覆盖“无确认不得发出 HTTP 请求”。
- 每个 RAGFlow 上传有可追溯的本地文件哈希、目标库、策略和远端文档 ID。
- 每个知识库回答均显示至少一个引用或明确无依据状态。
- 每项 Codex 任务均可追溯到任务包、授权模式、输出清单并可取消。
- 自动化测试不依赖真实 API Key，且脱敏测试覆盖 URL、请求头、错误和日志。

## 11. 实现时由构建者决定的细节

- 具体本地内容抽取库按格式覆盖、许可证、Windows 兼容性和维护状态选择；选择通过 ADR 记录。
- Everything DLL 的打包方式、CLI 回退与版本兼容策略以能力探测结果为准。
- RAGFlow 不同版本的端点、解析模板名称和问答机器人参数使用适配器能力发现与契约测试隔离。
- Codex Windows/WSL 的最佳启动命令通过阶段 4 的受控技术验证确定；在验证前不启用无人值守执行。

## 12. 需要的批准

批准本设计即批准：Windows-first Tauri 架构、默认本地优先/显式外发确认原则、当前仅交付阶段 0–1、模型与服务的上述配置策略，以及不将用户提供的服务凭据写入仓库。批准后，下一步是形成具体实施计划，再开始阶段 0 开发。
