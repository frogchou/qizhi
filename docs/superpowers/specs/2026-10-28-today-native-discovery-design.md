# 今日文件内建发现设计

## 意图

“今日”必须在用户没有安装或启动 Everything 时仍能发现其允许目录内当天修改的文件。Everything 从首界面的必需依赖降级为后续全机文件名检索的可选加速器。

## 目标

- 刷新“今日”只读取用户允许的本地目录，不读取文件内容。
- 复用现有扫描策略：系统目录、AppData、网络路径、重解析点和用户排除目录均不可访问。
- 文件扫描在 Tauri 后台线程执行，前端在刷新期间显示明确状态。
- 结果写入既有 SQLite 元数据表；返回格式不变。
- Everything 不可用不再导致“今日”空白或失败。

## 非目标

- 本阶段不建立常驻的全盘索引，不读取文件内容，也不支持网络磁盘。
- 本阶段不实现完整的 Everything 式即时文件名检索。
- 本阶段不创建或修改 Windows USN Journal。

## 方案比较

1. 继续把 Everything 作为必需服务：性能最佳，但要求用户安装、运行并保持相同权限级别；不符合本产品的即装即用目标。
2. 内建受限目录扫描：按需递归读取用户允许目录，以修改时间筛选当天文件。无外部服务、权限边界最清晰，首版可交付；大目录首次刷新会较慢。
3. 内建 USN 常驻索引：NTFS 上性能最好，但需要卷级日志解析、文件 ID 到路径映射、日志截断恢复和非 NTFS 回退，属于独立后续里程碑。

本次选择方案 2。方案 3 在内建扫描稳定后单独设计和实施；Everything 作为可选连接器保留。

## 架构

- 新增 `NativeFileDiscovery`，实现现有 `FileDiscovery` 接口。
- 每个允许根目录使用不跟随重解析点的深度优先遍历；仅收集常规文件，并用文件元数据修改时间过滤半开区间 `[今日零点, 明日零点)`。
- 扫描服务继续执行稳定性检查、策略复核、路径规范化和 SQLite 写入。
- `get_today_snapshot` 与 `refresh_today` 移至后台阻塞任务，避免长目录扫描卡住应用界面。
- 设置页把 Everything 描述为可选加速器；“今日”不再读取其状态。

## 约束

- Windows 首发；实现仍需在非 Windows 平台安全编译。
- 不新增网络、模型或文件内容读取能力。
- 不以管理员权限运行栖知。
- 最多在界面中展示既有扫描服务的结果上限；不因结果上限跳过安全校验。

## 验收

- 即使 Everything DLL 或服务不可用，创建在允许目录内、修改时间属于当天的文件会在刷新后出现。
- 允许根外、排除目录、重解析点与目录项不被收录。
- 无匹配项时显示“没有发现”而不是连接故障。
- 扫描命令不依赖 Everything SDK 或 `es.exe`。

## 后续 USN 里程碑

在 NTFS 卷上读取已有 USN Journal，仅处理当日变更，并维护目录文件 ID 映射。日志缺失、截断或非 NTFS 时回退到本次的受限目录扫描。该里程碑需要独立的卷能力探测、断点存储和恢复测试。
