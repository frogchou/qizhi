# 设置页分类导航设计

## 目标与原因

栖知的设置项已经从最初的扫描范围扩展到服务连接、JEV 价值评估、今日总结和 Codex 工作。继续在一个纵向页面中堆叠会导致查找困难、滚动距离过长，也不利于后续增加模型或工具。因此设置页改为与最初原型一致的二级分类导航，右侧一次只展示一类设置。

## 范围

- 保留现有设置数据结构、命令调用、凭据存储和保存/测试逻辑。
- 调整 `SettingsPage` 的信息架构、组件分组、导航状态和样式。
- 增加针对分类切换、内容可见性和输入状态保留的前端测试。
- 不在本次新增尚未实现的快捷键、通用设置或关于页功能。

## 分类

1. **扫描与隐私**：扫描范围、排除目录、文件类型、目录聚合阈值和保存扫描规则。
2. **连接服务**：本地 NTFS 索引器状态、OpenAI、TypeSafe AI/JEV 和 RAGFlow 的地址、密钥、测试及保存。
3. **价值评估**：JEV 评估说明、分级标准、价值阈值和保存操作。服务凭据与业务判断标准分开管理。
4. **今日总结**：总结模型和可无限增加的提示词模板。
5. **Codex 工作**：Codex 项目与会话使用的默认设置。

没有实际内容的分类暂不显示，避免出现空页面；后续增加新功能时只需新增导航项和对应面板。

## 布局与交互

- 设置页标题下方是两栏工作区：左侧为固定宽度的分类导航，右侧为当前设置面板。
- 默认打开“扫描与隐私”；当前分类使用绿色背景、左侧强调线和 `aria-current` 标记。
- 切换分类只改变可见面板，不卸载其他面板，确保用户尚未保存的输入不会丢失，也不会重复请求配置。
- 右侧内容区域独立滚动，应用主侧栏和设置分类导航保持稳定。
- 错误信息显示在当前设置工作区上方，切换分类后仍可见，直到下一次相关操作清除。
- 窄窗口下二级导航改为顶部横向滚动栏，内容恢复单列，不能产生页面级横向溢出。
- 各分类沿用现有卡片、按钮和输入框风格，减少大块空白，并统一标题、说明和操作区间距。

## 可访问性

- 分类区域使用独立的 `nav` 标签和明确的 `aria-label`。
- 每个分类按钮通过 `aria-controls` 关联内容面板，并用 `aria-current="page"` 表示当前项。
- 隐藏面板不进入键盘焦点和读屏顺序。
- 保留现有输入框标签、状态提示和按钮名称。

## 方案取舍

### 采用：二级分类导航 + 单一可见面板

最接近原型，查找成本低，适合设置项继续增长，也能清楚区分服务凭据和业务规则。

### 未采用：同页折叠面板

改动较小，但页面仍然很长，用户仍需滚动寻找分类，长期扩展性不足。

### 未采用：每个分类独立路由

可以提供深链接，但当前桌面设置无需浏览器式导航；会增加路由、返回和状态同步复杂度，收益有限。

## 验收标准

- 首次进入设置默认只看到“扫描与隐私”的内容。
- 五个分类均可切换，非当前分类内容不可见。
- 在某分类输入未保存内容，切换离开再返回后内容仍保留。
- 原有保存扫描规则、服务测试/保存、JEV 标准、总结模板和 Codex 设置行为不变。
- 常见桌面窗口和窄窗口均无元素遮挡或横向页面滚动。
- 设置专项测试、前端完整测试、类型检查、构建和相关端到端界面测试通过。
