# 栖知流式今日总结与按钮优化设计

## 意图

让用户点击“生成今日总结”后立即获得明确反馈，并在等待期间实时看到逐步生成、已经排版的 Markdown 内容；同时修正分段按钮箭头不明显、右侧圆角失效的问题。

## 目标

- 点击主按钮或提示词菜单项后立即打开总结弹窗。
- OpenAI Responses SSE 文本增量通过 Tauri Channel 逐段传给前端，而不是等待完整响应。
- 弹窗区分“正在生成、已完成、失败”三种状态。
- 内容使用安全的 Markdown 组件渲染标题、段落、列表、引用、链接和代码块，不直接显示 Markdown 标记。
- 生成完成后才能复制、另存和上传知识库；失败时在弹窗内显示可读错误并允许关闭。
- 分段按钮形成一个视觉整体，箭头清晰，左右两端圆角正确，菜单不被裁切。

## 非目标

- 本次不实现中止 OpenAI 请求；用户关闭弹窗后，当前请求可在后台结束，但其后续事件不再更新已关闭弹窗。
- 不改变提示词管理、文件选择规则、总结文件保存与知识库上传协议。
- 不允许模型输出的原始 HTML 直接注入页面。

## 方案与取舍

### 方案 A：Tauri Channel + `react-markdown`（采用）

后端逐条解析 `response.output_text.delta` 事件并经 Tauri Channel 发送；前端收到增量后立即更新弹窗，通过 `react-markdown` 渲染。优点是端到端真实流式、Markdown 支持完整且安全；代价是增加一个小型前端依赖和流式事件协议。

### 方案 B：Tauri Channel + 自制 Markdown 子集解析器

不增加依赖，但表格、嵌套列表、链接、代码块和流式未闭合标记容易出现不一致，不采用。

### 方案 C：立即打开弹窗但仍等待完整结果

只改善等待反馈，不满足真实流式输出要求，不采用。

## 交互设计

1. 用户选择文件并点击总结按钮。
2. 前端立即创建弹窗状态，显示模板名称、文件数量、“正在生成”状态和轻量加载动画。
3. 后端完成本地校验与文件读取后发送 `started`，随后连续发送 `delta`。
4. 前端将增量合并成 Markdown，弹窗内容区自动保持在底部；用户主动向上滚动后停止自动跟随。
5. 后端发送 `completed` 并返回最终总结，前端使用最终内容校正流式缓冲，启用复制、另存和上传。
6. 任一阶段失败时，弹窗保留已生成内容并显示错误，不再只使用页面悬浮提示。

## 流式协议

前端命令抽象接收可选事件回调，Tauri 实现内部创建 `Channel<WorkSummaryStreamEvent>`：

- `started`：模板标题和文件数量已确认。
- `delta`：新增 Markdown 文本。
- `completed`：是否截断等结束信息。

命令仍返回最终 `WorkSummary`，以保持现有保存、复制和上传逻辑稳定。测试替身可以直接调用事件回调，无需依赖真实 Tauri Channel。

## Markdown 安全与显示

- 使用 `react-markdown`，不启用原始 HTML 插件。
- 为标题、段落、列表、引用、代码块和链接提供栖知风格样式。
- 链接在系统浏览器中打开并使用安全的 `rel` 属性。
- 流式过程中允许不完整 Markdown 短暂按普通文本处理；完整标记到达后自动重排，不使用 `dangerouslySetInnerHTML`。

## 按钮结构

使用外层 `.summary-action` 负责菜单定位；内层 `.summary-split-button` 负责统一背景、圆角和 `overflow: hidden`。箭头区宽 40px，使用 18px SVG、较粗描边和略深背景，右侧圆角由容器裁切保证。菜单放在内层之外，因此不会被裁切。

## 验证

- Rust：SSE 增量回调顺序、完成状态、错误状态。
- React：点击立即出现弹窗；增量逐步出现；完成前操作禁用、完成后启用；Markdown 标记转为对应 DOM。
- 样式：分段按钮结构、箭头 SVG、右侧圆角和菜单层级。
- 完整运行 Rust/前端测试、类型与格式检查、生产构建和 Windows 安装包构建。
