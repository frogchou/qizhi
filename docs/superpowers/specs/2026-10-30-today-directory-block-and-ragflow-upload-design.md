# 今日目录屏蔽与知识库上传设计

## 意图

让用户能从“今日”列表直接消除不希望继续发现的目录，并在明确选择目标知识库后，把单个已发现的工作文件交给 RAGFlow 建档与解析。

## 目标

- 右键文件选择“屏蔽该目录文件”后，将该文件的父目录加入用户自定义排除目录；当前列表和缓存快照立即不再显示该目录的文件。
- 已保存的排除规则尽力同步到内置 NTFS 索引服务；同步失败不撤销本地隐私规则，也要记录诊断日志。
- 右键文件选择“上传到知识库”后，弹出对话框加载可访问的 RAGFlow 知识库，由用户选择一个目标知识库、可选的知识库内目录，以及是否立刻启动解析。
- 上传操作只能上传仍存在、仍在允许扫描范围内、且未被排除的文件。用户点击“上传”前不读取或传输文件内容。
- RAGFlow 上传成功后，按用户选择启动解析；若上传成功但解析启动失败，要清楚区分并返回文档标识。

## 非目标

- 不在本批次做多文件批量上传、自动价值判断、知识库自动推荐、文件内容预览或重复检测。
- 不允许页面自行传输本地文件；所有文件读写和 HTTP 上传都由 Rust 后端处理。
- 不覆盖知识库级的默认切片策略。文件级解析方式将沿用目标知识库设置，避免对用户已有的知识库配置产生意外影响。

## 约束

- 沿用 Tauri + React + Rust 现有架构，HTTP 使用 `reqwest`，不调用 shell 或 curl。
- RAGFlow 使用 `POST /api/v1/datasets/{dataset_id}/documents` 上传，再使用 `POST /api/v1/datasets/{dataset_id}/chunks` 启动内置切片流程；API Key 只能来自 Windows 凭据存储。
- 目录和文件权限一律由 `ScanPolicy` 进行后端校验；缓存过滤必须在规则保存后立即生效。
- 不把 API Key、文件内容或完整 RAGFlow 原始响应写入日志。

## 方案

### 方案 A（采用）：上传时继承目标知识库的解析设置

上传对话框只暴露目标知识库、可选知识库内目录和“立即开始解析”。RAGFlow 的知识库本来定义了解析/切片配置；上传后按其配置解析，行为可预测且无需前端猜测不同版本的 parser_config 字段。

### 方案 B：上传时让用户选择文件级切片方式

上传后需要 PATCH 文档设置并处理各类 parser_config，RAGFlow 版本差异较大，且会让用户在缺乏上下文时覆盖知识库策略。本批次不采用，后续可以作为高级设置。

## 主要流程

1. 用户在今日条目右键，选择“屏蔽该目录文件”。应用计算父目录、保存规则、向索引服务配置新规则，并返回按新规则过滤的今日快照。
2. 用户在今日条目右键，选择“上传到知识库”。界面加载知识库，展示文件名、大小和本地路径，用户选择目标与选项后确认。
3. 后端从数据库取得文件记录，重建当前扫描策略并验证文件仍可访问；通过 multipart 上传给 RAGFlow。若勾选解析，则提交新文档 ID 开始解析。
4. 界面显示成功、部分成功或失败信息；不会把文件路径/内容以外的敏感配置泄露到页面或日志中。
