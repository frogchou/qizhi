# 知识库对话界面设计

## 意图

将知识库页实现为接近已确认原型的工作对话界面：用户在主区域发问、阅读 RAGFlow 检索与 Agents 回答，并在右侧独立选择检索范围和查看近期问题。

## 目标

- 保留原型的三栏骨架：应用侧栏、主对话区、右侧检索范围栏。
- 主区以对话轮次呈现问题与回答；检索片段成为回答的可展开引用来源，不再作为页面底部瀑布。
- 右栏提供可折叠、可多选且可滚动的知识库下拉选择；Agents 也可独立多选。
- 显示 RAGFlow 连接状态与本次会话的近期问题；近期问题可一键再次填入对话框。
- 第一轮问题使用主区居中的输入框；已有对话后改用底部固定的跟进输入框。
- 内层对话区域独立滚动，应用侧栏与右侧资源栏不随消息滚动。

## 非目标

- 不变更 RAGFlow 的数据集、检索或 Agents 接口。
- 不在本轮实现跨应用重启的聊天历史持久化、附件上传或资料审核开关。
- 不伪造 Agent 回答；每个成功或失败的 Agent 结果都保留真实状态。

## 方案比较

1. 保持当前上下分区：实现代价低，但与原型结构相反，且检索结果继续破坏阅读流。
2. 对话主区 + 固定右侧资源栏：匹配原型，使范围选择不干扰阅读，并能把片段作为可追溯引用呈现。
3. 弹窗选择资源：页面更干净，但增加操作步骤，也偏离原型的可见范围。

采用方案 2。用户已经明确将所提供的原型作为结构参照，本文件只记录将既有多选能力映射到该结构的实现决定。

## 交互与状态

1. 页面加载时并行读取数据集和 Agents；资源清单在右栏展示。
2. 用户从“知识库（N）”下拉面板多选数据集，并在 Agents 面板多选 Agents。
3. 在初始输入框或底部跟进框提交问题。若至少选择一个资源，主区立即追加用户消息并执行现有 `queryRagflowKnowledge`。
4. 成功后在同一轮助手消息中显示 Agent 回答；检索片段折叠为“引用来源（N）”，可在回答下展开阅读。
5. Agent 单项失败仅在该 Agent 回答块显示错误，不影响其他结果。
6. 每个成功提交加入近期搜索；点击近期问题将其放入当前输入框。

## 视觉系统

- 背景为低饱和白绿；主区使用开放式画布，而不是整块结果卡片。
- 深墨绿用于标题、选中态与发送按钮；浅鼠尾草绿用于导航与选择态。
- 主区最大阅读宽度约 880px，右栏固定约 330px；输入框为细边框、轻阴影的横向工具条。
- 用户消息为浅灰绿气泡；助手消息是白色、细边框的阅读面板；引用卡片紧凑横向排列。
- 右栏由检索范围、连接状态、近期检索三张紧凑卡片组成。

## 验收

- 页面首屏结构、标题层级、输入框、右栏位置与原型一致，且不出现页面底部的并列结果瀑布。
- 选择多个知识库和多个 Agents 后，传给现有后端的 `datasetIds` 与 `agentIds` 不变。
- 单次查询后，用户问题、至少一个真实回答或检索提示、以及可展开的来源同时保留在同一对话轮次。
- 资源或消息过多时，仅消息区和下拉资源列表滚动；应用整体不滚动。
