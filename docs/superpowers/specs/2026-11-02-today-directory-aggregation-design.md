# “今日”目录聚合与变化树设计

## 背景与意图

“今日”当前把 NTFS 索引发现的文件平铺成表格。一个目录在短时间内出现数百或数千个文件时，单文件列表既不能表达目录结构，也迫使用户逐个勾选文件后才能生成总结。栖知只能可靠知道“哪些文件在什么时间发生了变化”，不能可靠推断这些变化来自克隆、下载、编译或人工编辑，因此本设计不引入 Git、应用历史或行为归因。

本期在现有 NTFS 文件索引之上增加一层通用的“目录变化树”：大量相关文件按目录聚合，用户可逐层展开、按目录选择并直接用于总结；少量文件仍以紧凑表格行展示。

## 目标

- 当同一目录分支出现大量今日文件时，用一个目录条目代替大量平铺文件。
- 优先呈现更具体的目录，例如 `项目A`，而不是宽泛的 `D:\工作`；展开后继续呈现 `src` 等更具体的子目录。
- 目录条目支持展开、收起、打开所在位置、整体勾选和目录级总结。
- 现有“今日 / 过去五天”、文件类型筛选、通配符搜索、排序、JEV 状态、右键菜单和单文件知识库上传继续可用。
- 聚合阈值由用户在设置中调整，默认值为 5。
- 大目录按需读取下一层，避免一次在页面中渲染几千行。

## 非目标

- 不判断文件变化是 Git Clone、下载、复制、生成还是人工编辑。
- 不引入 Git 分支、提交、Diff 或其他面向程序员的专用概念。
- 不建立完整磁盘目录浏览器；树中只展示所选时间范围内符合扫描、排除和文件类型规则的变化文件。
- 不改变 NTFS 索引服务采集文件变化的方式，也不让目录聚合阈值影响底层索引范围。
- 本期不实现长期活动归因、跨目录智能合并或由大模型为目录命名。

## 已考虑的方案

### 方案一：前端收到全部文件后临时聚合

改动最少，但仍需一次向界面发送并保存全部文件，几千项时刷新、筛选和展开的开销仍然存在。目录规则还会散落在前端，难以在“今日”和“过去”之间保持一致。

### 方案二：后端生成变化树，前端按层展开（选定）

后端复用本地文件数据库，按当前时间范围和过滤条件计算目录统计；首页只返回顶层展示项，展开时再查询下一层。目录级选择在后端解析成受当前安全策略约束的文件集合。该方案保持栖知的通用性，同时能控制大目录的 UI 和 IPC 开销。

### 方案三：把目录活动持久化为新的索引表

长期查询最快，但需要数据库迁移、增量一致性和索引生命周期管理。当前目录树可以由已有文件记录快速计算，暂不值得增加持久化复杂度。若以后扩展到数月工作历史，再单独评估。

## 用户界面

### 主列表

“今日”仍使用现有页面框架和紧凑表格，但表格中的展示项变为两类：

- **目录组**：文件夹图标、展开箭头、目录名称、相对路径、变化文件数、涉及子目录数、最近变化时间、类型概况和操作。
- **文件**：保留现有文件图标、名称、时间、来源、价值评估和操作。

目录行在视觉上与文件行一致，不使用大型卡片。目录名称为主信息，统计信息使用较弱的次级文字，例如“37 个文件 · 4 个子目录”。点击箭头或目录名称展开下一层；双击或“打开”操作使用资源管理器打开真实目录。

目录展开后以缩进层级显示子目录组和文件。树只在表格的文件名列形成层级，时间、价值和操作列保持对齐。目录本身不显示虚假的 JEV 评分；价值列显示其后代文档的真实汇总，例如“3 个有价值 · 8 个待评估”。

### 选择与总结

- 文件复选框行为保持不变。
- 勾选目录表示选中该目录下当前时间范围、当前文件类型过滤条件内的全部可见变化文件；不要求先展开。
- 目录存在部分已选后代时显示半选状态。
- 更改文件类型筛选或搜索条件后，清除已有目录选择并提示用户重新选择，避免目录复选框在后台悄悄改变所代表的文件集合；单文件选择与新条件取交集。
- 目录操作菜单增加“总结此目录”。它使用当前默认总结模板并立即打开现有流式总结窗口；总结按钮的下拉菜单仍可选择其他模板。
- 页面顶部“生成今日总结”继续总结用户选择的目录组和文件，不自动选择全部文件，避免在无法判断文件来源时把大批无关文件提交给模型。

### 搜索与排序

- 没有搜索词时使用目录变化树。
- 输入通配符搜索词后，保留目录上下文，但只展示包含匹配文件的分支；没有匹配后代的目录不显示。搜索词属于选择范围，例如搜索 `*.docx` 后勾选目录只选择匹配的 Word 文件。
- 文件类型筛选在聚合之前执行。“文档与文本”不会让代码文件参与目录计数、选择或总结；“源代码”同理。
- 同一层级内，目录始终排在文件之前。时间排序使用目录后代中的最近变化时间；名称排序使用目录或文件名称。展开状态不改变排序规则。

## 目录聚合规则

### 基本统计

后端根据已通过以下约束的文件构建内存目录树：

1. 当前时间范围（今日或过去五天）；
2. 允许扫描目录；
3. 系统和用户排除目录；
4. 设置中启用的文件大类；
5. 页面当前文件类型筛选和通配符搜索。

每个目录节点计算：

- 直接变化文件数（用于判断是否聚合）；
- 后代变化文件数；
- 含匹配后代的直接子目录数；
- 最近修改时间；
- 文件类型计数；
- JEV 状态计数。

当目录的**直接**变化文件数达到阈值，或含变化的直接子目录数达到阈值时，该目录可作为聚合节点。后代文件总数只用于展示和选择，不用于把所有祖先都判为聚合节点。阈值使用“大于等于”语义；默认 5 表示第 5 个符合条件的直接文件或直接子目录出现时开始聚合。

### 更具体目录优先

允许扫描根目录永不直接作为可见聚合项。构建每一层时按以下规则压缩宽泛容器：

1. 从扫描根开始向下检查变化分支，找出每条分支中最深的聚合目录。
2. 首页不直接裸露最深聚合目录，而显示其直接父目录作为上下文；展开父目录后显示最深聚合目录。多个最深聚合目录具有同一父目录时，父目录只显示一次。
3. 如果一个目录没有直接变化文件且只有一个包含变化的子目录，则折叠无意义的单一路径，直到到达上述上下文父目录。
4. 如果父目录本身含有未被子目录组覆盖的直接文件或小分支，展开后同时显示更具体的目录组和剩余文件。
5. 一个文件在同一层只属于一个展示分支，不重复计数或重复总结。

例如 `D:\工作\项目A\src` 有 30 个变化文件，而 `D:\工作` 只是容器，首页显示 `项目A`；展开后显示 `src`。如果 `项目A\docs` 也达到阈值，`src` 与 `docs` 在 `项目A` 下并列。

### 未达到阈值的内容

未达到聚合阈值的文件直接显示。小目录不会为了表现目录结构而强制产生额外行；其文件名通过相对路径或悬浮提示保留所在目录信息。这样少量文件仍能快速访问，大量文件才进入树形浏览。

## 后端与接口设计

现有 `TodayFile` 和文件数据库继续作为事实来源。新增面向界面的工作区查询模型，而不是修改 NTFS 索引协议：

- `WorkspaceQuery`：时间范围、文件类型筛选、通配符搜索、排序和聚合阈值。
- `WorkspaceEntry`：`kind`（directory/file）、稳定的本地条目标识、显示名称、规范路径、层级、统计、最近修改时间；文件项继续携带文件 ID 和 JEV 状态。
- `WorkspacePage`：当前目录的直接展示项、总匹配文件数及是否还有子层级。

新增或扩展 Tauri 命令以支持：

- 读取顶层变化项；
- 按目录路径读取下一层；
- 将目录选择解析为当前允许范围内的文件 ID；
- 打开目录；
- 使用目录选择生成总结。

目录选择超过现有单次 20 个文件限制时，使用分层总结：先按每批最多 20 个文件生成局部总结，再将局部总结综合为最终结果。开始多批总结前，界面显示最终文件数和预计批次数并要求用户确认；流式总结窗口展示批次进度和实际采用文件数。用户取消时不发起模型调用。批内仍遵守现有内容大小、隐私和文件类型安全限制，单个失败批次应明确报告，不能静默生成不完整总结。

所有目录参数在后端再次规范化，并通过当前 `ScanPolicy`、排除目录和 `FileTypeFilter` 校验。界面传入的路径不能绕过扫描边界。目录选择在真正生成总结时重新查询，防止展开后文件移动或规则变化造成越权。

默认扫描范围可能同时包含用户目录、桌面、文档和图片等嵌套根。构树前每个文件只归属于与其路径匹配的最长允许根，避免重复计数、重复选择和重复总结。父目录、子目录和单文件混合选择在后端解析后统一按文件 ID 去重。

旧的 `TodaySnapshot.files` 接口在迁移期间保留供现有测试和回退使用；新页面稳定后再决定是否移除，避免一次性破坏已有文件操作、上传和 JEV 更新流程。

JEV 自动评估不再依赖前端收到全部 `snapshot.files` 才启动。后端按时间范围、安全策略和文档类型查找待评估记录，评估结果仍持久化到现有表；构树时读取这些结果生成目录价值汇总。前端只负责显示状态和触发刷新。

## 设置

在“设置 → 扫描与隐私”中增加独立小节“今日页面展示”：

- 字段名称：`目录聚合阈值`
- 默认值：`5`
- 有效范围：`2–100`
- 说明：`同一目录达到此数量的变化文件或变化子目录后，在“今日”中折叠为目录组。`

该设置属于界面组织方式，不发送给 NTFS 索引服务，也不触发磁盘重新索引。保存成功后返回“今日”页面或下一次查询时立即使用新阈值。配置缺失或旧版本升级时自动使用 5；非法值由前后端共同拒绝。

首版将该字段加入现有本地扫描规则配置，以复用已有 JSON 持久化和设置保存提示。保存时比较旧、新扫描字段：只有允许根、排除目录或文件类型发生变化才重新配置索引器；仅修改展示阈值时只保存本地配置并刷新页面查询。

## 状态与错误处理

- 展开目录时显示行内加载状态，不阻塞整张列表。
- 子层查询失败时只在该目录行显示重试入口，不清空已加载的其他内容。
- 聚合计算失败时回退到现有平铺文件表，并显示自动消失的提示；不会把“没有文件”误报为索引服务不可用。
- 文件在展开期间消失时，从下一次查询和选择解析结果中移除，并在总结窗口中报告实际采用的文件数。
- 阈值修改不会中断正在生成的总结；新阈值只影响下一次工作区查询。

## 性能边界

- 目录树基于数据库查询得到的受限文件集合在内存中构建，不重新遍历磁盘。首版按时间范围从数据库读取完整受限集合并构树，按层加载指 IPC 与 UI 只返回/渲染当前层，不承诺数据库逐层查询。
- 首页和每次展开只序列化当前层条目；不渲染折叠目录的全部后代。
- 同一次查询中缓存目录统计，避免为每个节点重复扫描文件集合。
- 对极端目录设置单层展示上限并提供继续加载；具体页大小由实现者根据现有表格性能测试确定，默认建议 200 项。
- 路径比较沿用 Windows 不区分大小写的规范化规则，避免同一目录因大小写差异重复出现。
- “过去五天”必须分页取完索引服务结果后再构树；若服务或数据库只能返回截断结果，页面必须明确标记“统计不完整”，不能把前 5000 项伪装成完整目录统计。

## 测试与验收

### 后端单元测试

- 5 个文件时按默认阈值生成目录组，4 个文件时保持文件项。
- 5 个变化子目录可触发聚合。
- 扫描根和单一路径容器被折叠，更具体的 `项目A` 成为顶层项。
- `项目A` 展开后能显示达到阈值的 `src` 和未聚合的零散文件，且无重复文件。
- 排除目录、文件类型过滤和通配符搜索在聚合前生效。
- 目录选择只解析当前策略允许、当前过滤条件内的文件。
- 最深聚合目录在首页由其直接父目录提供上下文，展开后层级稳定且共同父目录不重复。
- 嵌套扫描根下的同一文件只出现和总结一次。
- 折叠目录中的待评估文档仍会进入后端 JEV 队列，评估完成后目录汇总正确更新。
- 超过 20 个文件的目录按 20 个一批生成局部总结并综合；未确认前不调用模型，失败批次不会被静默忽略。
- 阈值 2 和 100 有效，越界值被拒绝，旧配置默认迁移为 5。

### 前端测试

- 目录行可展开、折叠，并正确显示加载、空和失败状态。
- 目录复选框支持全选、半选和取消；筛选变化后选择数量正确更新。
- 搜索条件变化时清除目录选择并提示；搜索后的目录选择只包含匹配文件。
- “总结此目录”立即打开流式总结窗口，并使用目录最终解析出的文件数。
- 文件行现有打开、右键、上传知识库和 JEV 展示行为不回归。
- 今日与过去页面使用相同聚合规则；搜索和排序不会造成横向溢出或丢失层级。
- 设置页能读取、修改、保存阈值，并显示明确的成功或错误提示。

### 手工验收场景

1. 在一个允许目录中新建 4 个文档，刷新后仍看到 4 个文件行。
2. 新建第 5 个文档，刷新后变为一个目录组；展开可看到 5 个文件。
3. 构造 `项目A/src` 与 `项目A/docs` 两个大分支：首页显示 `项目A`，展开后显示 `src` 和 `docs`。
4. 将类型切到“文档与文本”，代码文件立即退出计数、目录树和总结范围。
5. 勾选一个包含大量文件的目录并生成总结，无需逐个勾选；总结窗口报告实际使用文件数。
6. 把阈值改为 10 后返回“今日”，目录组织立即按新阈值变化，且不启动 NTFS 重建。

## 实现者可决定的细节

- 内存树节点和稳定条目标识的具体 Rust 类型。
- 单层分页的精确大小和加载控件文案。
- 在保持现有绿色视觉体系、紧凑行高和无横向溢出的前提下，展开箭头、缩进线和统计徽标的具体样式。
- 旧快照接口的最终移除时机，但本期必须保留兼容或完整替换其所有调用与测试。
