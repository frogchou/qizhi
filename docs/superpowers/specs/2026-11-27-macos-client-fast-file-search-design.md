# 栖知双端客户端与 macOS 快速文件查找实现方案

**日期** 2026-11-27

**对应文档** [开发计划](../plans/2026-11-27-macos-client-fast-file-search.md)

## 要实现的体验

Windows 用户升级后可以继续使用已有工作目录、设置、凭据和工作记录，文件发现仍由现有 NTFS/USN 服务负责。macOS 用户可以安装栖知，选定一个或多个工作文件夹，使用原有的“今日／过去”、资料筐、总结、知识库、Codex 工作台和智能工厂。Mac 首版同时提供独立的“快速查找”入口，键入几个字就能在这些文件夹里按文件名或路径查找，包括很久没有改动过的文件。

两个平台继续共用 Tauri、React 界面与 Rust 业务代码。日后改进工作列表、总结或资料交接时，共享功能在两端一起验收。文件发现、目录规则和本机操作按系统选择各自的实现。

## 当前代码和保护边界

- Windows 自带索引服务读取 NTFS 元数据和 USN 变更记录。“今日／过去”把候选写入应用 SQLite，再由工作列表查询、分组和处理。设置保存和排除目录也会同步给该服务。 [现有文件发现](../../../apps/desktop/src-tauri/src/commands/today.rs) · [索引设置](../../../apps/desktop/src-tauri/src/commands/settings.rs)
- 评估、总结、知识库上传和 Codex 交接依赖应用文件记录及后端目录权限检查。Mac 接入需要提供可复核的文件记录，单纯返回一个路径无法接通整条流程。 [文件记录](../../../apps/desktop/src-tauri/src/database/repositories/file_repository.rs) · [Codex 交接](../../../apps/desktop/src-tauri/src/commands/codex_handoff.rs)
- 现有 Windows 回归下限包含本次基线 `4793917` 的三项修复：指定子目录时识别所属卷、同步到本轮开始时确定的日志边界就结束、普通搜索词可匹配中文文件名片段。Windows 安装、服务协议、服务数据库、凭据标识和原有命令契约沿用当前实现。 [卷识别](../../../apps/desktop/src-tauri/src/ntfs/volume.rs) · [日志同步](../../../apps/desktop/src-tauri/src/ntfs/service.rs) · [文件分组与搜索](../../../apps/desktop/src-tauri/src/today_workspace.rs)

## 搜索方式的选择

| 做法 | 体验和代价 |
| --- | --- |
| 查询 Spotlight 已建好的索引 | 接入快，首次使用能利用系统已有结果。覆盖范围和更新进度跟随 Spotlight 的索引及排除设置。 |
| 每次搜索遍历目录 | 做法简单。文件越多，输入时等待越久，重复查询也会重复访问磁盘。 |
| **栖知维护自己的文件索引（推荐）** | 首次读取选定目录的文件元数据。日常搜索查 SQLite，后台根据 macOS 文件变动更新。栖知可说明实际覆盖范围、建库进度和权限状态。 |

Mac 首版使用第三种方案。文件发现只访问用户选定且系统允许读取的本机 APFS 工作目录，使用普通用户权限。首发建议以 Apple 芯片为目标，最低 macOS 版本在首个真机构建和依赖验证后定档。Intel、网络盘、外接卷、云端占位文件、全盘索引和全文搜索保留为后续独立范围。Windows 首版沿用现有入口，新增全范围快搜可在后续评估独立接入。

## Mac 索引如何工作

1. **首次建库。** 在设置中选择工作目录后开始后台工作，先接收 FSEvents，再分批枚举文件元数据并补处理建库期间的变化。SQLite 索引置于应用数据目录，与 Windows 服务索引及业务数据库分别管理。首次按目录展示进度，已完成的目录可先提供结果。
2. **日常更新。** 合并短时间内的通知，重新检查受影响的文件或子目录，处理新增、修改、改名、移动和删除。每个卷的文件变化、待补扫状态和对应事件位置同事务提交。同卷受影响目录都已更新或已持久标记待补扫，才推进事件位置。正常刷新同步待处理变动并读取已提交索引。应用完全退出时停止监听，重开后从已保存的位置续接。事件丢失、位置失效或卷身份不符时，标记相关目录更新中并完整核对该目录。批次以本轮收到的事件边界结束，后来的事件进入下一轮。
3. **范围变化和异常。** 新规则保存成功后立即生效，旧批次凭规则版本取消或在发布前被丢弃。排除路径要从结果和操作入口立即消失，再由后台清理索引。启动、回到前台和查询时复核根目录访问状态，扫描遇到权限错误时同时记录受影响的子目录。发现权限不可用即隐藏相应结果并提示原因，操作时还要复核具体文件。若暂时无法判定目录状态，按未覆盖处理。构建失败的临时结果和事件位置一起丢弃。
4. **记录与隐私。** 保存原始路径、体积、创建和修改时间、卷标识与文件标识，以及栖知观测到的变动时间。用卷和文件标识并结合可用的创建信息识别同名替换。搜索忽略大小写并统一 Unicode 等价形式，文件定位、授权与索引身份保留实际路径和卷的语义，以支持区分大小写的 APFS。系统目录和应用自身数据目录排除优先，跳过符号链接及跨卷挂载。索引阶段只读元数据，遇到正文操作仍按现有业务流程由用户触发。

## 两个入口和资料交接

| 入口 | 查询和操作 |
| --- | --- |
| 今日／过去 | 共用 Mac 索引，按本机日历日期筛选创建、修改和在线观察到的变动，保留现有分组、搜索、排序和批选。在线观察到改名或移动时记录观察时间。首次扫描、离线补读、补扫只用可核对的创建或修改时间归类，同时校正当前名称和路径，避免把应用重启时间当成文件变更时间。 |
| 快速查找 | 在完整工作目录范围搜索，包含普通文件，按字面片段匹配文件名或完整路径，无时间限制。文件名完全匹配、文件名包含、路径包含依次优先，同级按最近修改和稳定记录键排序。默认取前 50 条，提供“加载更多”。空输入提示输入关键词。改输入时只显示最新请求的结果。 |

快速查找用 SQLite FTS5 的三字符索引处理长词，常见的一两个中文字由独立的短词索引处理。索引字段只含名称和路径，输入按普通文本解释。工作列表继续使用现有文件类别和匹配规则。快搜支持打开、Finder 定位和复制文件。加入资料筐时沿用资料筐的文件类型与权限检查，通过资料筐可继续交给 Codex 或智能工厂。工作列表上的评估、总结和知识库上传沿用各自的现有约束。

快搜返回由 Rust 生成的记录键。打开或处理时，后端重新检查当前规则、路径、存在性和文件身份，然后复用现有文件操作或资料筐服务。工作列表使用稳定的应用文件记录 ID。同一身份的普通刷新使用原记录，移除旧项只作用于对应的 Mac 来源和范围。并发换规则、文件被删或同名替换时，旧结果提示刷新，避免处理另一份文件。

## 其他平台适配

| 能力 | Mac 处理 |
| --- | --- |
| 目录设置和过滤 | 首次由用户选择目录，空范围可持久保存。范围比较用原生路径规则，系统排除与用户排除优先。 |
| 文件右键和本机操作 | 用 Finder 和系统默认应用完成定位、打开与复制文件。工作列表的文本编辑和删除走对应系统能力，保留现有操作确认和后端复核。 |
| 凭据 | 使用系统钥匙串保存模型、RAGFlow、JEV 和企业连接等密钥，通过现有 `SecretStore` 接口读取。Windows 继续使用原凭据名和引用。 |
| Codex | 从已打包应用启动本机 Codex，支持系统环境发现和用户选择可执行文件。以平台适用的方式检查连接和权限，真实验证资料边界、任务对话与生成物。 |
| 安装与更新 | Mac 首版按站外分发、签名公证的 DMG 交付，使用普通用户权限。Windows 继续产出原有 NSIS 安装包和服务。 |

## 验收与停止条件

- Windows 用基线数据、规则及旧版安装包做升级测试。结果、分页和批选与基线一致，已有记录与凭据可读，服务安装、升级、卸载和日常刷新成功。正常刷新耗时在同机同数据对照中，P95 相对基线增加不超过 10%。超出即定位原因并重新验收。
- Mac 在本地 APFS 上用 10 万条固定测试数据验收中英文、单字、双字、扩展名、路径片段和历史文件。建议目标为索引就绪时，键入到首屏完成渲染 P95 不超过 150 毫秒（含界面防抖），受监控的单个文件变动到结果更新 P95 不超过 3 秒。用安装包分别记录首次建库耗时、恢复耗时和索引磁盘占用，结合首轮实测给首次建库定发布门槛。性能值是拟定的发布目标，须在记录机型与数据量后实测。
- Mac 在安装包上跑通今日、过去、快搜、Finder、钥匙串重启、资料筐、总结、RAGFlow、JEV、Codex 与智能工厂演示。企业模式用测试配置实测连接与一次资料交接。系统权限拒绝、目录排除、同名替换和事件丢失都要有独立结果。
- Windows 回归失败时停止发布共享变更。Mac 索引异常可停用该能力或只重建 Mac 索引文件，并保留业务数据库、用户配置和钥匙串。Mac 的索引恢复和双端安装验收完成后再发布对应安装包。
