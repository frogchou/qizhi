# 今日总结设计

## 意图

让用户从“今日/过去”文件列表中明确选择工作材料，快速套用一个可维护的总结模板，通过已配置的 OpenAI 兼容服务生成 Markdown 结果，并在不建立应用内历史记录的前提下复制、另存或上传到 RAGFlow 知识库。

## 目标

- 让列表复选框真正支持单选、当前筛选结果全选/取消全选，并始终展示已选文件数量；切换“今日/过去”时清空选择，避免跨时间范围误提交。
- 把“生成今日总结”改为分体下拉按钮：主按钮使用默认模板生成，箭头菜单列出所有模板供快速选择；没有选中文件、没有可用模板或正在生成时禁止提交。
- 在设置中管理多个总结模板。每个模板包含标题、提示词、排序位置和“默认模板”标记；支持新增、修改、删除、排序和设为默认。
- 使用 OpenAI Responses API 优先直接提交用户选中的文件；当兼容服务明确不支持 Responses 或文件输入时，自动改为本地提取文本并调用 Chat Completions。
- 总结结果以 Markdown 弹窗展示，支持复制、另存为 `.md` 和上传到 RAGFlow 知识库。
- 用户点击生成前不读取或传输文件内容；点击生成即表示对当前已选文件和模板的一次性授权。

## 非目标

- 不自动选择文件，不因为 JEV 判定“有价值”就自动提交。
- 不在栖知数据库中保存总结正文或总结历史。
- 不在本批次提供 Markdown 富文本编辑器、总结续写、多轮对话或流式输出。
- 不把总结结果自动上传知识库；必须由用户在结果弹窗中主动确认。
- 不让模板覆盖 OpenAI Base URL、API Key 或模型设置；连接配置仍由现有 OpenAI 设置区负责。

## 已确认方案

### 方案 A（采用）：直传优先、文本自动降级

首选 `/responses`，把受支持文件作为 `input_file` 与模板提示词放在一次请求中。对明确表示端点、请求类型或文件输入不受支持的 404、405、415，或可识别的 400 文件输入错误，改用本地安全提取，再调用 `/chat/completions`。鉴权失败、限流、服务端故障、网络错误和内容安全错误不降级，以免掩盖真实问题或重复计费。

优势是 PDF、Office、演示文稿和表格能尽量使用模型原生解析能力，同时兼容只实现 Chat Completions 的企业转发服务。代价是需要维护两种请求格式和严格的降级判定。

### 方案 B（未采用）：始终本地提取

兼容性和流量控制最简单，但会丢失 PDF 页面图像、PPT 图示、Office 嵌入对象和表格结构，降低总结质量。

### 方案 C（未采用）：只允许 Responses 文件输入

实现最直接，但企业转发服务不完整支持 `/responses` 时整个功能不可用，不符合当前部署环境。

## OpenAI 文件输入约束

- Responses API 支持 PDF、Word、PowerPoint、Excel、CSV、TXT、Markdown 等文件输入；Chat Completions 的文件内容部分只支持 PDF，因此文本降级必须由栖知读取并发送文本。
- 单文件和请求总量遵循官方 50 MB 限制。栖知额外采用更保守的原始文件总量上限 40 MB，避免 Base64 编码和 JSON 构造造成明显内存峰值。
- 单次最多选择 20 个文件。超过数量或总大小时在读取前拒绝，并显示可操作的中文提示。
- PDF 使用 `detail: low` 作为今日总结默认值，以控制图像 token；以后可在高级设置中开放。
- 直传请求使用单次 Base64 `file_data`，不先写入 OpenAI Files 存储，不产生需要清理的远端文件对象。
- 本地文本降级最多提取每个文件 50,000 个 Unicode 字符、全部文件合计 180,000 个字符；达到限制时在提示词中明确标注截断，不静默伪装为完整内容。
- 本地降级必须支持现代办公与文本格式 `.pdf`、`.docx`、`.pptx`、`.xlsx`、`.odt`、`.ods`、`.odp`、`.rtf`、`.txt`、`.md`、`.markdown`、`.csv`、`.tsv`，以及今日列表内可安全解码为 UTF-8 的源码和配置文件。旧版二进制 `.doc`、`.xls`、`.ppt` 若直传不可用则明确列为无法处理，不尝试不可靠的字节转文本。

## 模型与连接设置

- OpenAI 设置区增加“总结模型”文本字段，保存为非敏感配置；默认值为 `gpt-5.6`，用户可按企业转发服务实际模型 ID 修改。
- Base URL 和 API Key 继续沿用现有 Windows 凭据存储机制；日志不得记录 API Key、文件正文、Base64 数据或完整模型响应。
- 连接测试继续验证基础 API 可达性，不把 Responses 文件输入能力当作保存配置的前置条件；能力在第一次总结时探测并按本次请求降级。

## 默认总结模板

首次迁移预置以下模板，用户可以全部修改：

1. `今日工作总结`：按工作主题归纳完成事项、关键结论、产出文件、风险和下一步。
2. `一句话总结工作`：用一句清晰、具体、可汇报的话总结所选材料体现的工作。
3. `会议总结`：整理议题、重要讨论、决定、负责人、截止时间和待办；缺失信息不得虚构。
4. `实验总结`：整理目的、条件、过程、结果、异常、结论和后续实验建议；缺失信息不得虚构。
5. `翻译全文`：将所选内容翻译成简体中文，保留标题、层级、表格语义和专有名词；原文已是中文时进行忠实整理而非重复翻译。

`今日工作总结` 为初始默认模板。模板标题去除首尾空白后必须唯一，长度 1—60 字；提示词长度 1—4,000 字；至少保留一个模板，且必须且只能有一个默认模板。

## 设置界面

在 OpenAI 服务卡片下方增加“今日总结模板”区域：

- 每行展示拖动/上下移动控制、标题、默认标记、编辑和删除。
- “新增模板”打开内联编辑卡，包含标题与多行提示词；保存前在前端即时校验，后端再次校验。
- “设为默认”会立即更新列表中的默认标记，但只有点击“保存总结设置”才写入数据库。
- 删除默认模板时自动把列表第一项设为默认；最后一个模板不可删除。
- 采用整组保存事务：任何一项无效则全部不写入，避免模板列表部分更新。

## 今日页选择与生成交互

- 每个文件复选框受控于 `selectedFileIds`；表头复选框只作用于当前经过标签、类型和搜索过滤后可见的文件。
- 表头复选框支持未选、全选和部分选择状态。过滤条件变化不会丢弃已选项，但按钮旁始终显示总计 `已选 N 个`，避免隐藏选择不可见。
- 切换“今日/过去”、删除文件或屏蔽目录后移除已经不在当前快照中的选择。
- 主按钮显示 `生成今日总结`；点击主区使用默认模板。点击箭头展开模板标题列表，当前默认模板带“默认”标记。
- 选择模板后立即开始生成并关闭菜单。生成期间按钮显示 `正在总结…`，禁止再次请求；文件列表仍可滚动，但复选框锁定，确保提交内容与用户看到的一致。
- 请求失败以悬浮提示和结果弹窗中的明确错误显示；不得把原始服务响应直接暴露给用户。

## 后端生成流程

1. 前端提交 `fileIds` 和 `templateId`，不提交本地路径、提示词正文或 API Key。
2. 后端从数据库重新取得模板和文件记录，重建当前扫描策略，验证每个文件仍存在、仍在允许范围内、未被排除且为普通文件。
3. 后端在读取前验证文件数量和总大小；任何文件无效则整体拒绝，并列出安全的文件名，不做部分总结。
4. 构造开发者指令：要求只基于提供的文件、用 Markdown 输出、明确区分事实和推断、不得虚构缺失信息。用户模板作为用户要求，文件按确定顺序附加。
5. 尝试 Responses 文件输入。若命中严格的“不支持文件输入”条件，记录不含内容的诊断信息并进行一次本地文本降级；其他错误直接返回。
6. 解析模型响应并要求非空 Markdown 文本。返回正文、使用的模板标题、文件名列表、实际处理方式（`fileInput` 或 `extractedText`）和可选的截断提示。

### 降级错误白名单

- `/responses` 返回 405 或 415 时允许降级。
- `/responses` 返回 404 且响应为空、为普通 `Not Found`，或结构化错误 `code/type` 为 `not_found`、`unsupported_endpoint` 时允许降级；若错误明确指出模型不存在，则不降级。
- 返回 400 时，只有结构化错误参数指向 `input_file`、`file_data` 或请求内容项，并且 `code/type` 为 `unsupported_value`、`invalid_content_type`、`unsupported_content_type`、`unsupported_file`，或消息同时包含文件输入字段与“不支持/无法识别”语义时允许降级。
- 401、403、408、409、429、所有 5xx、网络错误、模型不存在、上下文超限、内容安全拒绝和普通参数错误一律不降级。
- 每次用户操作最多执行一次 Responses 请求和一次降级请求，不递归重试；日志只记录分类结果和 HTTP 状态。

### 输出完整性

- Responses 明确返回 `incomplete` 状态，或 Chat Completions 返回 `finish_reason: length` 时，不自动重试，避免重复计费和生成内容漂移。
- 如果响应中已有非空正文，结果弹窗展示正文并显示“模型输出可能被截断”的醒目警告；复制、另存和上传仍可使用，由用户决定是否采用。
- 如果截断响应没有正文，则按生成失败处理。

## 结果弹窗

- 顶部显示模板标题、文件数量和处理方式；正文区域以可选择、保留换行的 Markdown 源文本展示，首发不引入 Markdown 渲染依赖。
- 输入或输出发生截断时，在正文上方显示不会随滚动消失的警告，并把同样的警告作为 Markdown 引用追加到另存和上传内容的开头，防止不完整结果脱离界面后失去上下文。
- `复制`：把完整 Markdown 正文复制到系统剪贴板，并显示短暂成功提示。
- `另存为`：打开系统保存对话框，默认文件名为 `YYYY-MM-DD-模板标题.md`；后端只写入用户明确选择的路径，使用 UTF-8。
- `上传到知识库`：打开与文件右键上传一致的知识库选择流程，默认文档名同上，可选择知识库内目录和“立即开始解析”。后端直接以 UTF-8 Markdown 字节构造 multipart 上传，不创建未清理的本地临时文件。
- 上传成功、上传成功但解析失败、上传失败三种状态沿用现有 RAGFlow 文案和语义。
- 关闭弹窗会丢弃正文；若用户尚未复制、保存或上传，不额外弹出二次确认。

## 数据结构

- 新增迁移 `0008_summary_prompts.sql`：
  - `summary_prompt_templates(id, title, prompt, sort_order, is_default, created_at_utc_ms, updated_at_utc_ms)`。
  - `openai_summary_settings(id=1, model)`。
  - 在迁移中插入五个默认模板和默认模型。
- 模板正文和模型 ID 不属于秘密，可以存入 SQLite；API Key 仍只保存在 Windows Credential Manager。
- 不新增总结历史表。

## 命令边界

- `get_summary_settings()`：读取模型和有序模板列表。
- `save_summary_settings(input)`：事务保存模型与整个模板列表。
- `generate_work_summary(input { file_ids, template_id })`：校验文件并返回一次性总结结果。
- `save_summary_markdown(input { content, path })`：把结果写入用户通过保存对话框选择的 `.md` 路径；拒绝空正文和非 `.md` 扩展名。
- `upload_summary_markdown(input { content, filename, dataset_id, parent_path, start_parsing })`：复用 RAGFlow 客户端上传内存中的 Markdown 内容。

前端 `QizhiCommands` 增加对应类型，生产实现仍通过 Tauri `invoke`；测试客户端使用同一接口。

## 错误处理

- 未选择文件：`请先选择要总结的文件。`
- 模板已被删除或无效：重新加载设置并提示用户选择其他模板。
- 文件移动、被排除或无权限：整体取消，并列出最多五个文件名。
- 请求过大：在读取或编码前提示数量/大小限制。
- Responses 不兼容：自动降级一次，不弹两次错误。
- 本地无法解析且直传不可用：列出无法处理的文件，不提交残缺集合。
- 模型明确报告输出长度截断：有正文则展示并标注不完整，无正文则失败；不自动重试。
- 模型返回空内容或不可识别结构：提示 `OpenAI 返回的数据无法识别。` 并写入脱敏诊断日志。
- 保存或上传失败：结果弹窗保持打开，正文不丢失，允许再次操作。

## 安全与隐私

- 只处理数据库中存在且通过当前 `ScanPolicy` 的文件 ID；前端路径不可信。
- 仅在用户主动点击模板生成后读取和传输所选文件。
- 日志只记录请求模式、文件数量、扩展名集合、总字节数、HTTP 状态和错误类别，不记录文件正文、Base64、完整本地路径、提示词正文或模型响应。
- OpenAI 与 RAGFlow 请求均使用现有 Rust HTTP 层，不启动 PowerShell、curl 或其他命令行程序。

## 验收标准

- 勾选、全选、部分选择和切换时间标签行为符合设计；没有选择时不能生成。
- 设置页能创建至少三个模板、修改、排序、设为默认并在重启后恢复。
- 默认模板主按钮和下拉模板选择都会把正确的模板 ID 与所选文件 ID 交给后端。
- 支持的转发服务通过 Responses 文件输入生成；不支持时只降级一次并通过 Chat Completions 生成。
- 非兼容错误不会被错误降级；文件越界、移动、排除、过大和不可解析均有明确提示。
- 结果可以复制、保存为 UTF-8 Markdown，并能作为 `.md` 文档上传到选定 RAGFlow 知识库。
- 总结正文不会写入应用数据库或诊断日志。
