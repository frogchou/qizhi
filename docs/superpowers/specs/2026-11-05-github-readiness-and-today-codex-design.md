# GitHub 发布准备与“今日 → Codex”设计

## 目标

在不改变现有工作流的前提下，修复“今日”资料发送到 Codex 的字段契约，支持从页面顶部批量发送当前勾选的文件或目录，并把仓库整理成适合公开阅读的中英文项目说明。

## 范围

- Tauri 命令边界统一接受前端 camelCase 字段，兼容 `queryId`、`fileIds`、`directoryIds`。
- “发送到 Codex”位于“今日/过去”页面顶部操作区，选择一项或多项后启用；发送成功后沿用现有清空选择逻辑。
- 根目录项目说明提供中文和英文入口；桌面端、前端功能区、Rust 核心模块提供职责与入口说明。
- 检查公开仓库忽略规则和潜在密钥文件，不把用户配置、日志、数据库、构建缓存或凭据写进仓库。

## 非目标

- 不改变 Codex 项目、会话和资料快照的现有业务规则。
- 不在本次工作中推送 GitHub、改写 Git 历史或选择开源许可证。
- 不为说明文档重新设计产品界面。

## 方案

1. **在 Rust/Tauri 边界修复（采用）**：给枚举字段启用 camelCase，保持整个前端命令 API 一致，并用 JSON 反序列化测试锁定契约。
2. 前端改发 snake_case：能绕过错误，但破坏现有 TypeScript 命名习惯，也容易让其他来源再次分叉，因此不采用。
3. 双字段兼容层：适用于已发布的多版本客户端；当前版本尚未形成需要长期兼容的旧协议，暂不增加复杂度。

文档采用 `README.md`（中文）与 `README_EN.md`（英文）互链；模块说明同样使用双文件，避免在一个超长文档中折叠两种语言。

## 验收

- camelCase 的 Today/Recent handoff JSON 可成功反序列化。
- 页面顶部按钮能把多个选中的文件/目录一次发送到 Codex。
- 前端、Rust 定向测试与完整检查通过。
- 公开说明不含真实 API Key，生成目录和本机状态被忽略。
